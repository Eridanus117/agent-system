# Route B：从单篇概念文档到可扩展教学系统

<!-- markdownlint-disable MD013 MD024 -->

> 核验时间：2026-08-12。本文回答一个窄问题：怎样让 AI 持续教一位已有后端工程经验、正在转向推理基础设施的成年人，并在概念增长到数百个后仍能知道“先学什么、学会没有、何时复习”。
>
> 产物性质：**教学法综述 + Route B 设计建议**，不是 `agent-control` 当前权威，也不实施系统、不重写现有学习内容。需要负责人确认的结论集中在文末“authority 候选”。
>
> 当前证据入口：本仓 `main` 尚无获认可的教学法知识包；本文把开放中的关联 [#157（Matt Pocock Skills 研究）](https://github.com/Eridanus117/agent-control/issues/157)和关联 [#170（vLLM 与推理 infra 学习单元）](https://github.com/Eridanus117/agent-control/issues/170)作为待核验任务证据，而不是当前权威。

## 结论先行

推荐把 Route B 从“文档集合”改成三层分离的教学系统：

1. **概念图**保存稳定概念 ID、先修依赖与辨析关系；只有 `requires` 形成 DAG，`contrasts-with`、`related-to`、`applies-to` 等关系不参与先修门控。
2. **教学资产**保存解释、图、worked example、练习、源码入口和来源；一项概念可以有多份资产，一份资产也可以覆盖多个概念，不再把“一概念 = 一文件”当成系统边界。
3. **学习者状态**保存每个概念的尝试、证据、最近检索、下次复习与失效原因；“掌握”是有时效和证据的状态，不是文档存在或读过一次。

每轮按同一个小循环运行：**先检索旧知 → 只教一个可消化增量 → worked example → 学习者独立做／解释 → 针对性反馈 → 教回 → 门控 → 安排延迟复习**。AI 最有价值的地方不是继续生成长文，而是根据现场表现调整提示量、回退到缺失先修，或把支持逐步淡出。

在现有 BM25 引擎上，概念图先做结构化硬筛，只允许“已满足先修且符合当前目标”的候选进入排序；BM25 再按问题词面从这些候选的教学资产中选最相关的一项。不要让全库裸检索决定课程顺序，也不要因概念数量达到几百就直接升级向量层。

## 研究口径与证据标记

本文把“来源距离”和“证据强度”分开，避免把一个经典名字误写成有效性证明。

### 来源距离

- **一手研究**：原始实验、原始理论论文或作者／产品的官方实现说明。
- **二手综合**：系统综述、元分析或对多项研究的学术综合；它离原始实验更远，但通常比单项实验更能说明可迁移性。
- **本次推断**：把研究结果映射到 Route B、成年人技术学习或当前 KB 架构；它是待验证设计判断，不是论文结论。

### 证据强度

- **A｜强**：多项受控研究的元分析／系统综述，且边界能与本任务对齐。
- **B｜中**：有原始实验和相邻领域复现，但效果依任务、先验知识或实施质量变化。
- **C｜有限**：主要是分类框架、设计启发或品牌化技巧，缺少对该方法整体的直接比较证据。
- **D｜设计推断**：可解释、可逆且值得试验，但尚未被本任务的真实学习数据验证。

## 一、教学法研究：14 种方法怎样用、哪里不能外推

| 方法 | 证据与主要发现 | 适用边界 | 对 AI 教成年工程师的判断 |
| --- | --- | --- | --- |
| **1. 间隔重复**（spaced repetition） | **A｜二手综合。** [Cepeda 等 2006 年综述](https://digitalcommons.usf.edu/psy_facpub/1771/)显示分散练习优于集中练习，最佳间隔随目标保持时间变化；课堂研究的[系统综述与元分析](https://pubmed.ncbi.nlm.nih.gov/40564553/)也报告中等总体优势。**一手实现说明。** [SM-2 的历史与公式](https://www-beta.supermemo.com/en/articles/history)来自 SuperMemo；[Anki 当前手册](https://docs.ankiweb.net/deck-options)明确区分 legacy SM-2 与可选 FSRS。 | 强证据支持“隔开复习”，不等于独立证明 SM-2 的每个参数最优；Anki 是实现载体，不是教学法本身。间隔应服从保持目标、历史表现与工作量，不能硬编码成普适的 1/3/7 天真理。 | **核心。** 为概念节点生成 `nextReviewAt`，优先复习到期且与当前新概念有关的节点；复习必须要求检索或应用，不能只是重新展示文档。 |
| **2. 主动回忆／检索练习**（active recall / testing effect） | **A｜一手研究 + 二手综合。** [Karpicke 与 Roediger 的实验](https://doi.org/10.1126/science.1152408)显示，掌握后重复学习对延迟回忆帮助很小，而重复检索带来显著长期优势；[40 多年迁移研究的元分析](https://pubmed.ncbi.nlm.nih.gov/29733621/)显示测试相对重读能产生中等迁移，但受题型、初始成功率和精细检索调节。 | 检索练习不是高压考试；若初次检索几乎必败且无反馈，可能只增加挫败。只问术语定义会训练术语，不自动迁移到诊断、设计或源码阅读。 | **最高优先级。** 每轮开场闭卷问一个旧概念，门控至少含一个新情境应用；失败后给提示和反馈，再次检索，而不是立刻贴出整篇答案。 |
| **3. 交错练习**（interleaving） | **A｜二手综合。** [59 项研究的元分析](https://pubmed.ncbi.nlm.nih.gov/31556629/)报告总体中等效应，但材料调节很强：相似类别辨析和部分数学任务受益，说明性文本结果含混，单词学习甚至更适合分块。 | 交错不是随机打乱所有内容。初学者仍需要先形成基本 schema；更适合混合容易混淆、需要选策略的相邻概念。 | **核心但延后。** 首次讲解保持局部连贯；练习与复习时交错 `prefill/decode`、`TP/PP/DP`、不同缓存策略等可辨析概念。 |
| **4. 精细加工／自我解释**（elaboration / self-explanation） | **B｜一手研究。** [Chi 等对 worked example 学习的研究](https://doi.org/10.1207/s15516709cog1302_1)发现，高表现者更频繁把步骤与原则连接并监控误解；[Renkl 等实验](https://pubmed.ncbi.nlm.nih.gov/9514690/)进一步研究了例子变式与引导式自我解释。 | “多说一点”不是精细加工。有效输出要建立因果、条件、对比或预测；无约束解释可能流利却错误，必须有外部反馈。 | **核心。** 让负责人回答“为什么”“如果约束改变会怎样”“它与相邻概念差在哪”，Agent 针对遗漏的因果边反馈。 |
| **5. 双编码**（dual coding） | **B｜二手综合。** 多媒体学习研究支持文字与相关图示的互补呈现；[Mayer 对多媒体原则的研究综合](https://www.cambridge.org/core/books/abs/cambridge-handbook-of-cognition-and-education/how-multimedia-can-improve-learning-and-instruction/C71FE6F3416AA7B3C1995264570F3E9A)强调减少无关加工，[概念／知识图元分析](https://doi.org/10.3102/00346543076003413)也显示节点—连线图通常有助保持。 | “加一张图”不等于双编码；装饰图片、重复屏幕文字与旁白可能增加负荷。对抽象技术概念，图必须表达数据流、状态转移、拓扑或约束关系。 | **高适配辅助。** 只为关系密集概念配小图，例如调度循环、KV block 映射、TP×PP 拓扑；图后仍要求学习者用语言解释。 |
| **6. Worked examples** | **A｜一手研究 + 二手综合。** [Sweller 与 Cooper 的代数实验](https://doi.org/10.1207/s1532690xci0201_3)奠定 worked-example effect；[2023 年数学元分析](https://eric.ed.gov/?id=EJ1364058)总体支持正确示例，且设计特征影响效果。 | 对新手和高元素交互任务最有用；随着熟练度上升，完整步骤会冗余。示例若只有答案没有理由，帮助有限；不能替代独立练习。 | **最高优先级。** 用“完整跟踪 → 缺步完成 → 独立追踪”的 fading 序列，例如先跟一条 request 的 scheduler/KV 路径，再让负责人补全关键状态变化。 |
| **7. 认知负荷理论**（CLT） | **B｜一手理论与实验 + 新近二手综合。** [Sweller 1988](https://doi.org/10.1207/s15516709cog1202_4)指出手段—目的搜索会占用 schema 获取所需容量；[2025 年 expertise-reversal 元分析](https://doi.org/10.1016/j.learninstruc.2025.102142)显示低先验学习者受益于高支持，高先验学习者更受益于低支持。 | CLT 不是“所有页面都要短”；关键是管理同时交互的元素、消除无关负荷，并按先验知识改变支持。主观“感觉难”也不是精确的负荷测量。 | **核心控制原则。** 一次只引入一个高交互增量；先测已有后端／分布式知识，已会的部分直接跳过，避免对专家重复解释。 |
| **8. Feynman 技巧／以教促学** | **B/C｜相邻一手研究，品牌化流程证据有限。** [准备教学的实验](https://doi.org/10.3758/s13421-014-0416-z)改善文本回忆与组织；[实际教学与教学预期比较](https://doi.org/10.1016/j.cedpsych.2013.06.001)支持“真正解释给别人”带来的生成性加工。没有证据表明流行的四步 Feynman 配方作为整体优于所有替代法。 | 能流畅讲错；简单化可能删掉关键约束。必须让领域证据、反例或 Agent 纠错参与，而不是以“听起来简单”作为掌握标准。 | **核心检查，不是完整课程。** 每个节点末尾做 60–120 秒 teach-back：负责人向“会后端但不懂当前概念的人”解释，Agent只指出最关键错误／缺边，再要求重讲。 |
| **9. 刻意练习**（deliberate practice） | **A｜二手综合。** [Macnamara 等元分析](https://www.psychologicalscience.org/journals/psychological-science/0956797614535810/)显示刻意练习重要但远非全部：解释的表现差异随领域变化，在教育与职业任务中尤其有限。 | 需要明确目标、可重复任务、即时高质量反馈和略超当前能力的难度；“做很多题”或“累计一万小时”不是充分定义。 | **适合技能层。** 把概念落到 trace、配置取舍、源码定位、故障诊断等真实微任务；不把阅读时长当进度。 |
| **10. 掌握学习**（mastery learning） | **A｜二手综合。** [108 项受控评估的元分析](https://doi.org/10.3102/00346543060002265)显示考试表现和态度总体改善、弱生受益更明显；同时可能增加学习时间，自定进度课程还可能降低完成率。 | “达到 80%”不是跨领域的自然常数。门控要与目标能力一致，并允许重教／重试；过密门控会造成流程税和中途退出。 | **核心结构。** 只有满足当前节点的解释 + 应用证据才开放依赖它的新节点；允许负责人显式跳过，但记录为未验证先修。 |
| **11. Bloom 分类** | **C｜原始分类框架 + 实证检验。** 修订版区分记忆、理解、应用、分析、评价、创造，并增加知识类型维度；[医学教育综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC4511057/)说明其常见用途。[对修订版内部假设的实证检验](https://pmc.ncbi.nlm.nih.gov/articles/PMC9727608/)同时表明类别关系比单一路径层级更复杂。 | 它分类目标，不告诉系统什么顺序最有效，也不证明所有学习必须逐级爬金字塔。动词本身也不能保证题目的认知深度。 | **只作覆盖检查。** 用来避免所有检查都停在“记住”：每个重要概念至少覆盖解释与应用；不把 Bloom 当调度器或掌握算法。 |
| **12. 最近发展区与脚手架**（ZPD / scaffolding） | **B/C｜一手理论／观察。** [Wood、Bruner、Ross 1976](https://doi.org/10.1111/j.1469-7610.1976.tb00381.x)描述 tutor 依据表现招募兴趣、简化任务、维持方向与示范；后续研究提醒 ZPD 与 scaffolding [不是同一个概念](https://www.sciencedirect.com/science/article/abs/pii/S2210656117301794)。 | 原始工作主要面向儿童；把它直接外推到成年工程师属于本次推断。帮助过多会替代思考，帮助过少会让检索反复失败。 | **高适配控制。** 提示阶梯固定为“澄清目标 → 指向相关原则 → 给局部线索 → 给缺步示例 → 完整示范”，下一次尝试减少一级支持。 |
| **13. Socratic tutoring** | **B｜小样原始研究 + tutoring 综合。** [Socratic 与 didactic tutoring 的直接比较](https://www.research.ed.ac.uk/en/publications/a-comparative-evaluation-of-socratic-versus-didactic-tutoring/)支持定向追问，但样本与领域有限；[人类与智能 tutoring 研究综述](https://doi.org/10.1080/00461520.2011.611369)更稳妥地支持“细粒度交互与适应”整体，而非某一问法必胜。 | 连续反问不是苏格拉底教学；新手缺 schema 时，直接说明 + 示例可能更有效。互动耗时高，也可能让负责人承担过多猜测成本。 | **选择性使用。** 用 1–2 个诊断性问题暴露模型；若答不出就切换显式教学，不能把“永不直接回答”写成产品原则。 |
| **14. 形成性评价**（formative assessment） | **A｜二手综合与批评。** [Black 与 Wiliam 综述](https://doi.org/10.1080/0969595980050102)支持让频繁反馈改变教学；[Shute 的反馈综述](https://doi.org/10.3102/0034654307313795)总结及时、具体、任务相关的反馈形状；[Bennett 的批评性综述](https://www.ets.org/research/policy_research_reports/publications/article/2011/imec.html)强调定义、测量和领域建模要求。更广的[反馈元分析](https://doi.org/10.1037/0033-2909.119.2.254)发现平均有益但超过三分之一干预反而降低表现。 | “问了一个问题”不算形成性：结果必须改变下一步。泛化表扬、自我层面的批评或答案倾倒都可能无效。 | **最高优先级。** 每次检查只输出最小可行动反馈，并改变路径：继续、补先修、换例子、增加／减少脚手架或进入复习。 |

### 哪些最适合当前学习者

负责人已有工程经验但目标领域知识不均匀，最适合的不是单一“最佳教学法”，而是一组互相制约的机制：

1. **主轴：检索练习 + worked examples + 形成性评价 + mastery gating。** 它们分别回答“能否从记忆取出”“有没有正确过程模型”“错误怎样改变下一步”“是否可以依赖这项知识”。
2. **跨轮保持：间隔重复 + 有目的的交错。** 前者抵抗遗忘，后者训练在相似方案之间作选择；交错只发生在已建立基本 schema 的概念间。
3. **理解检查：自我解释 + teach-back。** 负责人输出因果模型，Agent 用来源、反例与遗漏边纠正；这比问“懂了吗”可靠。
4. **支持调节：认知负荷 + 脚手架淡出。** 已掌握的后端基础不重复讲；对推理 infra 的新结构先示范再撤支持。
5. **辅助而非主轴：双编码、Socratic、刻意练习、Bloom。** 它们分别改善关系呈现、诊断互动、技能练习与目标覆盖，但不能单独承担路径、保持与验收。

[225 项 STEM 研究的主动学习元分析](https://pubmed.ncbi.nlm.nih.gov/24821756/)提供一个更高层的边界：让学习者产生可检查输出通常比持续听讲更有效。Route B 因此应把“负责人正在做什么”作为每轮核心，而不是以 Agent 输出的篇幅作为教学量。

## 二、可扩展结构：概念多了以后，什么应当成为结构

### 2.1 先分清四种对象

“单概念单文档”会混乱，根因不是 Markdown，而是把四种生命周期不同的对象绑在一起：

| 对象 | 回答什么 | 典型变化频率 |
| --- | --- | --- |
| **概念节点** | 这项可学习能力是什么，依赖什么，与谁易混淆？ | 低；稳定 ID 与边应尽量持久。 |
| **教学资产** | 用哪段解释、图、例子、练习、源码或论文教它？ | 中；可随版本、媒介和质量替换。 |
| **学习者状态** | 负责人对它有哪些即时／延迟证据，下一步是什么？ | 高；每次学习都可能变化。 |
| **会话记录** | 当时说了什么、试了什么、为何换路？ | 高且可归档；不应成为当前掌握状态的唯一来源。 |

因此，原子化的对象应是**一个可验收能力节点**，而不是强制的一页文件。`PagedAttention`、`KV block table` 和“分页消除逻辑连续与物理连续绑定”是否拆成一个或三个节点，要看它们能否分别出题、分别失败和作为别人的先修；文件大小不是判据。

### 2.2 七种结构方法的证据与职责

| 结构方法 | 有什么价值 | 在几百概念时的边界 | Route B 处置 |
| --- | --- | --- | --- |
| **先修依赖 DAG** | Knowledge Space Theory 从[知识状态与可达学习路径](https://arxiv.org/abs/1511.06757)建模；[ALEKS 的大规模实现回顾](https://doi.org/10.1016/j.jmp.2021.102512)展示了依知识结构做评估、学习与周期重评的可行性。 | DAG 只适合“必须先知道”的硬边；如果把相关、包含、相似、共同出现都塞成先修，会制造环和过度门控。边的正确性需要领域维护。 | **作为课程骨架。** 只允许 `requires` 参与 frontier 与门控；边必须能用一个失败例或学习理由解释。证据为一手／二手研究，具体字段为本次推断。 |
| **原子概念／Zettelkasten** | Luhmann 档案把卡片箱描述为连接导向的“第二记忆”和思考工具，[原始档案结构可复核](https://niklas-luhmann-archiv.de/nachlass/zettelkasten)。原子条目便于复用、链接和局部更新。 | 没有足够直接证据表明“原子笔记法”本身提升掌握；极细拆分会失去叙事、例子上下文和维护经济性。它服务写作／思考，不自动产生教学顺序。 | **借粒度原则，不照搬系统。** 节点按可验收能力拆分；解释与例子可保持成较长资产。证据强度 C。 |
| **概念地图** | [55 项研究、5818 人的元分析](https://doi.org/10.3102/00346543076003413)显示构建、修改或查看节点—连线图通常提高保持，但用法与比较条件带来明显异质性。 | 概念地图表达广义关系，不保证无环，也不自动区分先修与相似；一张含几百节点的全景图本身会过载。 | **作为局部视图。** 每次只展示当前节点的先修、相邻辨析与下游用途；底层仍保留类型化边。 |
| **螺旋课程**（spiral curriculum） | Bruner 传统强调在更高复杂度和新情境中重访同一主题；[Harden 与 Stamper 的定义性综述](https://doi.org/10.1080/01421599979752)概括为迭代重访并逐步加深。 | 概念合理但强比较证据不如 spacing／retrieval；若只是重复同一页，既不是螺旋也不产生迁移。 | **作为跨阶段编排。** 首次建立直觉，随后在源码、性能取舍、故障案例中重访；每次增加新关系或任务复杂度。证据强度 C/B。 |
| **渐进式披露**（progressive disclosure） | [分段效应元分析](https://eric.ed.gov/?id=EJ1217373)显示有意义、可控的分段能改善保持与迁移并降低总体认知负荷，但会增加学习时间。 | 这是呈现策略，不是知识结构；把重要内容藏到多层 UI 也会增加发现成本。 | **作为教学资产视图。** 默认只显示当前目标、最小模型与练习；按请求展开推导、源码、例外和证据。 |
| **知识图谱** | 教育 KG 的[系统综述](https://doi.org/10.1016/j.heliyon.2024.e25383)显示其常用于个性化、课程设计、资源推荐与问答；同时不同构建和评价方法差异大。 | KG 是通用数据结构，不是已证明的教学法。RDF、图数据库、embedding 与自动抽边会显著增加工程和校验成本；学习收益证据常与整个系统混在一起。 | **暂不建设完整 KG。** 用类型化 Markdown／JSON 概念图即可表达当前决定；只有跨域查询、并发维护或图算法成为真实瓶颈时再评估存储升级。证据强度 C/D。 |
| **间隔复习调度** | 来自前述 spacing 与 retrieval 证据；Anki 展示了按卡片历史安排 due queue 的成熟实现形状。 | 调度器只能决定“何时再试”，不能保证题目有效、答案理解或概念边正确。若新卡流入大于复习吞吐，会形成债务。 | **成为学习者状态的一等字段。** 新概念预算必须受 due queue 约束；复习题优先取新情境或相邻概念辨析。 |

### 2.3 平铺文档与概念图在规模上的可维护性

| 维度 | 平铺单文档 | 分层模块 | 类型化概念图 + 复习状态 |
| --- | --- | --- | --- |
| 初期编写成本 | 最低；一篇文章即可交付。 | 中；需要模块边界、顺序与检查点。 | 最高；需要稳定 ID、边类型、检查与状态模型。 |
| 单篇阅读连贯性 | 高；适合首次长读和分享。 | 高；模块能保持叙事。 | 取决于教学资产；图本身不提供叙事。 |
| “下一步学什么” | 靠目录、作者记忆或搜索结果猜。 | 固定顺序清楚，但跨模块适应有限。 | DAG frontier 能排除先修未满足项，并允许多条可达路径。 |
| 找出遗漏先修 | 隐藏在正文链接与口头假设中。 | 模块级可见，概念级仍可能隐藏。 | `requires` 可查询、审查和回退。 |
| 处理多个解释／版本 | 容易复制整篇或在一页累积例外。 | 可按模块版本化。 | 节点稳定，资产可按媒介、版本和难度替换。 |
| 学习进度 | “读过文件”通常成为错误代理。 | “通过章节检查点”较好，但粒度较粗。 | 每节点保存即时、应用和延迟证据；可表达 stale／due。 |
| 复习 | 依赖人记得回看。 | 可在模块末复习，时间适应弱。 | due queue 与新学习同一调度面。 |
| 几百概念后的主要风险 | 重复、孤岛、路径漂移、文档名字承担过多分类、检索命中不等于能学。 | 模块重排成本、跨域先修重复、固定路径对已有经验过教。 | 边维护税、错误先修导致错误门控、状态与内容不同步。 |
| 适合 BM25 的方式 | 全文召回强，但排序无法表达“现在能不能学”。 | 先按模块过滤，再排章节。 | 先按图 frontier 硬筛，再在允许资产内 BM25；结构与词法各司其职。 |

结论不是淘汰长文。关联 [#170（vLLM 与推理 infra 学习单元）](https://github.com/Eridanus117/agent-control/issues/170)这样的长文可以继续作为一份高质量**教学资产**；需要替代的是“长文文件树同时承担课程图、学习状态和复习队列”这一隐含模型。

## 三、渐进学习循环：“学一点 → 教一点 → 再学一点”怎样落地

### 3.1 概念节点的最小合同（设计建议）

```text
Concept
  id                稳定、可跨文件引用
  outcome           学习者最后能做什么，不写“了解 X”
  requires[]        硬先修；必须构成 DAG
  contrastsWith[]   容易混淆但不门控
  relatesTo[]       其他语义关系
  scope/version     适用领域、软件版本与失效条件
  assets[]          解释、图、worked example、练习、源码、来源
  checks[]          检索、应用、辨析、teach-back 的可评分检查

LearnerConceptState
  conceptId
  stage             unseen | learning | provisional | due | retained | stale
  evidence[]        题目、答案摘要、反馈、支持级别、结果与时间
  lastCheckedAt
  nextReviewAt
  invalidatedBy[]   版本变化、先修状态回退或证据过期
```

状态名只是设计建议，不是已批准 schema。关键不变量是：`stage` 必须能回到证据，`retained` 必须有延迟检索／应用，软件版本变化可以让既有状态变成 `stale`。

### 3.2 单轮协议

```text
恢复本轮目标与可用时间
        ↓
对到期旧概念做一次闭卷检索／辨析
        ↓
图硬筛：到期复习 或 requires 已满足的新节点
        ↓
只教一个增量：最小模型 + 相关图/反例
        ↓
完整 worked example → 缺步 example → 独立微任务
        ↓
形成性反馈：只指出最高价值差距，并调整提示级别
        ↓
负责人 teach-back；Agent 用来源和反例校验
        ↓
门控：继续 / 补先修 / 换资产 / 暂停 / 记入复习
```

一轮可以在任何门控点结束。系统不因“今天计划三项”就越过失败的先修，也不因一次答对就永久标记掌握。

### 3.3 Mastery gating

建议把门控定义为能力证据组合，而不是固定百分比：

1. **无资料解释**：能说出概念解决的问题、核心机制和至少一个边界。
2. **相邻辨析**：能解释为何当前情境选 A 而不是容易混淆的 B。
3. **新情境应用**：能完成一个未照抄 worked example 的微任务，或正确追踪关键状态。
4. **延迟保持**：隔一段与目标保持期相称的时间后，再次检索或应用成功。

前 1–3 项支持从 `learning` 进入 `provisional`；第 4 项才支持 `retained`。检查失败不等于“重读原文”：系统先区分是忘记、先修缺口、误概念、任务太难还是题目本身不良，再选择最小纠正。

### 3.4 自适应路径与复习队列

- 每轮先给到期复习一个有限预算，再引入至多一个主要新节点；具体比例应由真实使用决定，不预设永久数值。
- 新节点只从 `requires` 已满足的 frontier 中选择，再按当前长期目标、最近源码任务和相邻交错价值排序。
- 失败若指向明确先修，就沿 `requires` 回退；失败只与表达或题目有关时，换资产而不是修改图。
- 连续高质量表现时淡出 worked steps 和提示；低表现时只增加一级脚手架，避免一次性答案倾倒。
- 自报“会了”只降低诊断成本，不能替代检索；自报“完全不会”可以直接选择高支持资产。
- 新概念输入速度受复习债务约束。若 due queue 持续增长，系统先减少新概念，而不是继续扩库。

### 3.5 Teach-back 的最小协议

1. Agent 指定听众和时间盒，例如“向一个懂后端但没读过 vLLM 的工程师，用 90 秒解释 continuous batching”。
2. 负责人必须说明：问题、机制、一个对比例、一个边界；可以画简图，但不能看标准答案。
3. Agent 只返回三类反馈：**正确保留、关键缺边、会导致错误决策的误解**。
4. 负责人只重讲受影响部分；Agent 再给一个最小反例验证修正是否稳定。
5. 记录实际支持级别；靠完整提示完成只能算 `learning`，不能算独立掌握。

## 四、Matt Pocock 的可迁移教学结构

### 4.1 本次读了什么

- **一手核验。** 关联 [#157（Matt Pocock Skills 研究）](https://github.com/Eridanus117/agent-control/issues/157)固定了 `mattpocock/skills` 的提交、触发分层、代表 Skill、发布面和作者一手说明。本文复用了其中已核验的“一个 leading word + 一个可观察门 + 一个明确退出”，没有把 stars 或传播当学习效果。
- **一手核验。** [Total TypeScript 官方课程页](https://www.totaltypescript.com/)明确描述其 exercise-driven 流程：先给 problematic code 与简短任务，允许学习者使用文档和本地／嵌入编辑器独立尝试，之后再看作者解法；练习逐步相连，并在不同情境重复重要概念。
- **一手核验。** 公开教程把同一课拆成 [exercise 页面](https://www.totaltypescript.com/tutorials/beginners-typescript/beginner-s-typescript-section/working-with-arrays/exercise)和独立 solution；更高级的[解法页面](https://www.totaltypescript.com/workshops/advanced-typescript-patterns/classes/debugging-the-builder-pattern/solution)展示作者逐步读取类型反馈、尝试修改和解释为何有效。
- **二手／营销信号。** 课程页用户评价说明体验良好，但没有对照组、延迟测验或独立测量，不进入有效性结论。

### 4.2 可迁移的五段结构

1. **先制造真实、可见的反馈环。** TypeScript 课程不是先讲完整理论，而是让编译器错误把问题具体化。迁移到 infra：用 trace、简化调度表、显存分配图、配置差异或源码断点，让学习者能看到哪里不成立。
2. **题面短，问题真实。** 练习只提供完成任务所需上下文，避免把答案藏在长讲解里。这与 progressive disclosure 和认知负荷控制相符。
3. **先尝试，再看专家 worked example。** 学习者可以查官方文档，但必须先形成自己的路径；solution 展示的不只是最终代码，而是专家如何读信号、试错和解释。
4. **练习层层相接，又换情境出现。** 同一类型机制在多种使用场景重现，既形成局部 progression，也有交错与迁移机会。
5. **工具本身成为 formative feedback。** 编译器／编辑器给出即时、具体、任务层反馈；教学者围绕反馈校正 mental model，而不是只判对错。

### 4.3 不应照搬的部分

- Total TypeScript 的公开结构没有展示长期间隔复习、延迟保持证据或跨数百概念的学习者状态；Route B 需要补上，而不是把一串 exercises 当完整系统。
- 编译器提供确定反馈是 TypeScript 的领域优势；推理 infra 的很多取舍需要版本化源码、硬件条件与性能实验，不能假装每题都有即时单一真值。
- “先做题”对已有 schema 的工程师很合适，但全新、高交互概念仍应先给短模型或 worked example；这正是 expertise reversal 的边界。
- 关联 [#157（Matt Pocock Skills 研究）](https://github.com/Eridanus117/agent-control/issues/157)的“小而可组合、可观察门、明确退出”适合设计会话原语，不证明他的 Skill 发布结构就是课程知识结构。

## 五、Route B 的两个可信设计选项

### 选项 A：概念 DAG + 学习者状态 + 间隔复习 + teach-back（推荐）

**运行方式。** 类型化概念图决定可学 frontier；每个节点引用多种教学资产与检查；学习者状态记录证据与 due time；每轮执行第三节微循环。长文仍可作为“学习路径／叙事资产”，但不再是状态容器。

**适配负责人。** 高。能跳过已有后端基础，针对推理 infra 的局部缺口回退；teach-back 与源码／系统设计任务能利用工程经验，而不是从零课程化。

**扩展到几百概念。** 高。稳定 ID 和类型化边使重复、先修缺口、版本失效和跨域复用可被查询；局部视图避免一次展示全图。主要成本是边和检查的领域校验。

**维护成本。** 前期中高、后期可控。必须维护少量硬先修、能力检查和状态迁移；不建议一开始建设图数据库、自动知识抽取或复杂掌握模型。

**与现有 BM25 的结合。** 当前 `tools/kb_retriever/` 的真实合同是：调用方先给可信 `stage`／`object`，引擎做结构化硬筛，再对 `operation`／`signals.aliases` 做 BM25，只返回一张最短动作卡；它不支持拿任意学习文档直接推断课程状态。Route B 可复用这个**两阶段形状**：

```text
概念 DAG + 学习者状态
  → 硬筛 eligibleConceptIds（到期，或先修已满足）
  → 用当前目标／问题 signals 对 eligible assets 做 BM25
  → 返回一个概念的一项教学资产 + 来源／版本／证据
```

若未来要复用现有实现，需要新增独立的 teaching-card schema／adapter，并验证 parser 与输出合同；`_archive/knowledge/retrieval-cards.md` 不能兼任课程图，`oneLineAction` 也不能兼任完整教学资产。没有确认改述漏检以前，概念数量本身不构成向量检索升级理由。

**主要风险。** 错误先修边会让路径看起来“结构化却走错”；细粒度状态可能增加维护税；如果负责人不愿做短检查或复习，图会退化成更复杂的目录。

### 选项 B：分层课程模块 + 模块检查点 + 螺旋复访

**运行方式。** 以目标路线组织 6–12 个模块，每模块包含一段连贯叙事、若干 exercises 和一个综合检查点；模块内部固定顺序，模块间只维护少量前置关系。后续模块用新情境重访前面主题，复习以模块检查点为单位。

**适配负责人。** 中高。阅读和连续练习更自然，适合一段时间集中攻一个主题；但对“这个会、那个不会”的不规则先验适应较粗，容易重复或跳过隐藏先修。

**扩展到几百概念。** 中。几十个模块仍可维护；跨模块复用、细粒度复习和版本失效会越来越依赖人工目录与作者记忆，但显著优于平铺文档。

**维护成本。** 中低。作者只需维护模块顺序、入口、检查点和少量前置；重排整个模块时 diff 较大，但不需要每概念状态。

**与现有 BM25 的结合。** 模块 ID／检查点可作为结构化过滤键，BM25 在选中模块的标题、练习与源码入口中排序。接线简单，但只能回答“这个模块里哪段最相关”，难以判断某个概念是否到期、是否独立掌握。

**主要风险。** 固定路线再次把“内容顺序”误当“个人学习状态”；复习粒度过粗；跨域先修会复制到多个模块；几十轮后仍可能出现“读完模块但不知道哪些概念已经保持”。

### 选项比较

| 决定维度 | 选项 A：概念 DAG 循环 | 选项 B：模块课程 |
| --- | --- | --- |
| 渐进“学一点—教一点” | **最佳**；每节点都能独立运行与门控。 | 良好；以课／模块为增量，粒度较粗。 |
| 不规则既有经验 | **最佳**；按节点诊断与跳转。 | 一般；通常按模块跳过或重学。 |
| 数百概念的可发现性 | **高**；依赖、状态、到期分开查询。 | 中；目录清楚但跨模块关系弱。 |
| 延迟保持 | **原生**；每节点 due queue。 | 需另加模块复习表。 |
| 首版作者成本 | 较高。 | **较低。** |
| 叙事连贯性 | 依赖资产设计；不能只给卡片。 | **原生较强。** |
| BM25 接线复杂度 | 中；需图硬筛 + teaching adapter。 | **低**；模块硬筛 + 章节排序。 |
| 错误结构的影响 | 高；错边会误门控。 | 中；错序可由人工阅读绕过。 |
| 最适合的使用形态 | 高频、跨域、长期、个体化。 | 主题相对线性、低频、维护人力有限。 |

### 推荐与翻转条件

**推荐选项 A，但采用“薄图、厚资产”的边界。** 只把硬先修做 DAG，保留关联 [#170（vLLM 与推理 infra 学习单元）](https://github.com/Eridanus117/agent-control/issues/170)这类长文作为叙事资产；先验证学习循环和边维护，而不是建设通用知识图谱。推荐依赖 A 级的 retrieval／spacing／mastery／active-learning 证据，B 级的 worked example／expertise adaptation 证据，以及 D 级的 Route B 架构映射。

以下未知会翻转到选项 B：

1. 负责人真实使用主要是一次连续读完一个主题，很少跨轮回访，也不愿维护或完成节点级复习；
2. 近期规模长期停留在几十个概念、单一线性领域，先修分叉和跨域复用没有出现；
3. 领域专家无法以可接受成本校验 `requires` 和 checks，导致图错误率高于人工目录的路径税；
4. 负责人明显偏好完整叙事，节点跳转带来的上下文恢复成本高于个体化收益；
5. BM25 teaching adapter 的建设／维护成本显著高于模块内检索，而自然任务没有出现需要节点级召回的证据。

反过来，只要出现跨域跳转、重复解释、隐藏先修、复习债务或“读过却不会用”，这些都是维持选项 A 的直接信号。

## 六、验证建议（不在本交付实施）

设计决定获得授权后，先用一条 12–20 节点的小路线验证，不以“写完多少节点”验收：

1. 预先画出 `requires`、两个 `contrasts-with` 和每节点一个应用检查；边必须有人能解释。
2. 用同一批既有 Route B 资产，在选项 A 与模块式普通路径间比较真实体验，不为实验重复制造内容。
3. 观察：延迟检索／应用成功、回退先修次数、错误路径纠正成本、一次会话的负责人主动输出比例、复习债务、资产／边维护时间，以及 BM25 在结构硬筛后是否仍错选。
4. 预先规定翻转门：若图维护和状态记录没有减少路径错误或复习遗漏，退回模块；若模块持续出现隐藏先修和重复教学，保留图。
5. 单人样本只能证明“对负责人当前场景有用／无用”，不能推出通用教育产品效果；进入产品采用仍需要多轮真实使用证据。

## 七、authority 候选与非候选

以下是**设计建议／authority 候选**，均需负责人确认后才能进入 `authority/`：

1. **A1｜三层分离：** Route B 的概念结构、教学资产、学习者状态分开维护；文件不再等同概念或掌握状态。
2. **A2｜薄概念图：** `requires` 是唯一门控 DAG；关联、对比和应用关系保留为非门控类型化边，不建设完整通用知识图谱作为首版依赖。
3. **A3｜默认教学循环：** 检索旧知 → 单一增量 → worked example／练习 → 形成性反馈 → teach-back → mastery gate → 延迟复习。
4. **A4｜掌握证据：** “掌握”至少区分即时解释／应用与延迟保持；自报、阅读完成或单次选择题不能单独作为持久掌握。
5. **A5｜检索边界：** 图与学习者状态先做 eligibility 硬筛，BM25 只在允许的教学资产中排序；数量本身不授权向量层。
6. **A6｜保留长文：** 当前单篇学习文档作为可复用叙事资产继续存在，不要求按原子节点批量拆文档。

以下内容只是**研究结论或实施候选，不是 authority 候选**：

- 14 种教学法的证据综述与来源索引；它们进入正式知识前仍需逐条通过知识价值门、可信门和授权。
- 示例状态名、字段名、节点数、试验规模和任何复习间隔；这些应由后续合同和真实使用决定。
- Matt Pocock 模式的迁移分析；它支持 exercise-first 与可观察反馈环，但不授权复制课程或 Skill 结构。
- 任何图数据库、向量检索、知识追踪模型、自动抽边、UI、Hook 或定时器；本交付没有选择或实施这些技术。

## 八、知识维护回执

### 窄问题与适用范围

问题是“Route B 怎样教一位成年后端工程师技术概念，并在数百概念规模保持路径、掌握和复习可管理”；核验时间为 2026-08-12，直接服务 Route B 架构决定，不主张覆盖儿童教育、班级管理或通用课程平台。

### 找到并复用的当前结论

本仓没有找到已认可、范围匹配的教学法当前知识。关联 [#157（Matt Pocock Skills 研究）](https://github.com/Eridanus117/agent-control/issues/157)与关联 [#170（vLLM 与推理 infra 学习单元）](https://github.com/Eridanus117/agent-control/issues/170)仍是开放交付，因此只作为待核验证据复用；现有 `tools/kb_retriever/` 的 README、ADOPTION 与实现合同经本次工作区直接读取，可用于说明 BM25 的真实边界。

### 变化、冲突与缺口

- **缺口：** 当前内容资产没有稳定概念 ID、硬先修、学习者证据或 due queue。
- **缺口：** 学术文献很少直接比较“几百篇平铺 Markdown”与“类型化概念 DAG + 复习”对成年工程师的学习效果；本架构比较因此明确标为本次推断。
- **冲突：** 交错、Socratic、worked examples、反馈都存在显著边界或负效应条件，不能变成无条件规则。
- **变化风险：** Anki 调度实现、Route B 内容、vLLM 版本和 KB 检索器合同都可能继续变化；基础学习效应相对稳定，软件与本仓适配结论不是永久事实。

### 价值门与可信门

- retrieval、spacing、worked examples、mastery、formative feedback、concept maps：较可能在后续教学与系统设计中反复使用，**通过价值门**；本文已给出一手／二手来源、边界和最少复核，作为**可审查知识候选**通过可信门。
- Bloom、Feynman、ZPD、Socratic、Zettelkasten、knowledge graph：有设计价值但直接效果证据或本任务适配不足，**通过价值门但不能作为强效果知识**；保留 C/D 等级和翻转条件。
- Route B 选项 A 推荐：长期解释重要决定，**通过价值门**；尚无负责人真实使用实验，可信门只支持“设计候选”，不能写成已采用或已证明有效。

### 失效条件与下次最少复核

出现以下情况时重新核验对应结论：

1. 负责人确认新的学习目标、节奏或交互偏好，使本次“成年工程师、渐进跨轮学习”假设不再成立；
2. Route B 实际概念规模、边密度或维护成本与本文判断显著不同；
3. `tools/kb_retriever/` 不再使用 `stage/object` 硬筛 + BM25，或新增受验证的语义层；
4. 教学系统真实运行后，延迟保持、路径纠正或负责人注意力数据反驳推荐；
5. 需要更新工具实现事实时，先重读 Anki 当前手册和本仓 KB README／ADOPTION；需要更新核心学习效应时，先查本文元分析之后的高质量系统综述，而不是全量重做经典理论史。
