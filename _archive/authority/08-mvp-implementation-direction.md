# 首个 MVP 的最小实现方向

> 状态：当前权威。首个 MVP 方向已经进入实施；相关协作切片与运行入口已经建成并交付，证据最多支持“当前交付验收”。
> 当前职责：只承载当前实施架构、稳定入口、长期权限决定和明确非目标；逐次授权、命令级验收、提交号、故障与安装过程由对应 Issue、知识、研发记忆和 Git 历史保存。
> 历史起点：2026-08-09 曾选择“版本化文件为中心、先人工运行”；该表述不再定义活动任务当前事实的承载面。

## 当前实施架构

首个 MVP 已从早期方向选择进入实施，当前形成四层可恢复架构：

1. **版本化权威与行为资产**：`agent-system` 保存负责人确认的长期权威、入口版本化来源和需要版本管理的资产；当前公共远程为 `https://github.com/Eridanus117/agent-system`。
2. **GitHub 持久合同**：Issue／PR 保存意图、授权、决定、验收、任务图、交付来源和阶段边界回执；它们不能覆盖当前权威或负责人更新的明确指令。
3. **Orca 活跃运行面**：Run、Task、Dispatch、消息、Delivery 和 worker 生命周期只承载过程执行态；运行态不回灌为权威或持久授权。
4. **按需行为资产**：知识维护、问题求解治理、纠偏改进、受控协作、GitHub Issue 交付与 PR 整合分别由当前 Skill／Plugin 承载可重复行为；权威只保留职责、授权边界和失效条件，不固化易漂移版本表。

三类事实的唯一承载与 Orca 的产品边界见 [`04-collaboration.md`](./04-collaboration.md#产品事实三分)；本文件不建立第二套任务状态或生命周期语义。

## 当前交付与证据上限

当前已经建成并交付的窄能力包括：

- 可由普通 Windows Codex、Orca Codex 与 Claude 发现的 Agent 系统入口；
- 版本化权威、远程恢复和按需领域路由；
- GitHub 持久协作主干、Orca 薄运行适配与联邦式 Issue 子树工作流；
- 知识维护、问题求解治理、纠偏改进和受控协作等按需行为入口；
- 绑定当前交付物的审查、整合、父级回收与证据等级边界。

这些事实证明当前版本的入口和交付链已经通过当前交付验收，不证明自然任务中的长期低成本运行、产品采用、永久平台选择或长期依赖。后续是否保留、修改、退出或升级，继续由自然样本、能力回退和总体 ROI 决定。

## 稳定 Windows 入口

Windows Codex 的当前权威入口同时覆盖两种启动路径：

1. 未设置 `CODEX_HOME` 的普通 Windows 环境，使用默认 `C:\Users\<user>\.codex`；
2. Orca 宿主注入专用 `CODEX_HOME` 的环境。

版本化公共入口来源是 [`../entrypoints/agent-system.md`](../../entrypoints/agent-system.md)，仓库级 Codex 入口是 [`../AGENTS.md`](../../AGENTS.md)，Claude 通过 [`../CLAUDE.md`](../../CLAUDE.md) 导入同一入口规则。普通 Codex 与 Orca Codex 的 Plugin／Skills 存储已用 NTFS Junction 收敛为单份；配置文件与用户级 `AGENTS.md` 仍是两套独立文件，入口一致性继续由现有同步验收检查。Junction 消失或指向变化时，该安装事实失效，必须重新核验。

入口负责让 Session 找到当前权威、远端合同和条件性行为，不在用户级文件复制完整知识、状态机、工具命令或运行状态。

## Windows 默认执行权限

负责人在 2026-08-09 确认：

- Codex 继续使用 `approval_policy = "never"` 与 `sandbox_mode = "danger-full-access"`；
- 普通 Windows 与 Orca 两种 Codex 启动路径保持相同策略；
- Claude Code 继续使用 `bypassPermissions`；
- 不执行 Codex 工作区沙箱试点，不修改当前权限配置。

这是一项自主性优先的长期权限决定，不表示风险为零。只有出现权限相关误操作或损失、机器承载明显更高价值的私域资料或凭据、无人值守或多 Session 明显扩大影响范围，或者平台提供经真实任务证明几乎无摩擦的更小边界时，才重新进入 ROI 比较；在此以前不为权限策略建设自动切换机制。

## 当前授权边界与明确非目标

已经交付的能力各自由当时的明确合同授权；本文件只记录当前边界，不把历史授权扩张成开放实施权。任何新增仓库、用户级配置、Skill／Plugin、Hook、MCP、自动化、宿主权限或外部系统写入，仍需要当前任务合同覆盖。

当前明确不由本文件授权：

- 自动组波、自动派发、轮询、Webhook、常驻调度器、自动合并或无人值守升级；
- 把 GitHub、Orca 或当前 Plugin 直接确定为不可替换的永久平台；
- 批量吸收旧仓、旧 Issue、旧知识或历史实现；
- 建设正式知识平台、知识图谱、私域结构、翻译规范或资源监控系统；
- 把一次交付、一次并行样本或安装通过提升为产品采用、长期依赖或“漂移已经消失”；
- 超出具体 Issue 所有权的新配置、安装、删除、远端写入或并发范围。

最终仓库数量与职责、永久平台选择、自动化程度及当前窄能力以外的产品边界仍须以新证据和负责人决定推进。

## 守恒律与受限自清理

> 迁移来源：本节由 [`00-map.md`](./00-map.md) 按关联 [#181（常驻规则面分层收敛）](https://github.com/Eridanus117/agent-control/issues/181)迁入当前实施权威；总图只保留路由。授权与历史基线来源见[关联 #44（规则只加不减的收敛实施）决定回执](https://github.com/Eridanus117/agent-control/issues/44#issuecomment-5258111511)及[关联 #178（规则与 Skill 体系复杂度收敛）调研交付](https://github.com/Eridanus117/agent-control/issues/178#issuecomment-5267420521)。

**守恒律**：

1. **无条件入口不得超过当前规模**：始终被加载的入口正文（版本化来源 [`../entrypoints/agent-system.md`](../../entrypoints/agent-system.md) 及其安装副本）以已批 10314 个 LF 规范化 UTF-8 字节为上限；未来任何未批净增仍默认回退；
2. **Skill 描述预算封顶**：单个 Skill 的描述不得超过当前平台可承载的上限，也不得依靠被平台截断来维持；
3. **新增规则须写明置换对象**：向入口、Skill 描述或其他常驻规则面新增内容时，必须在同一次修改中写明被置换、压缩或删除的对象；只换不加。

守恒律约束常驻规则正文的总量，不限制按需读取的权威、知识和研发记忆展开必要细节；超出上限时的处置是回退新增，不是提高上限。

**受限自清理**：Agent 可以不逐次请求授权就降级自己创建的资产，但下列条件必须全部成立：

1. **对象受限**：该资产由 Agent 自建，且创建时已写明停止谓词，谓词经负责人确认；
2. **过程受限**：处置方式是就地降级，附一条回执，并保留一个波次的撤销窗口；
3. **边界受限**：不得触及外部依赖、已验收能力和授权边界条款。

任一条件不成立时仍需负责人决定。本条是预授权谓词的执行，不是开放授权：它不授权删除权威、卸载外部 Plugin、提高自动化程度，也不授权清理其他 Session 或负责人创建的资产。

此前“可观测数据的获取成本与决策价值比较”未覆盖规则正文体积、入口副本与描述截断的历史证据，现由上述 [#44](https://github.com/Eridanus117/agent-control/issues/44) 决定回执与 [#178](https://github.com/Eridanus117/agent-control/issues/178) 调研交付承载，不再占用启动总图。
