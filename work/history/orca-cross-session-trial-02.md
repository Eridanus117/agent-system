## 独立结论

新 Session 同意既有结论：

- 警告来自 Orca 专用用户配置和工作目录中项目配置的重复分层；
- Orca 用户级 `notify` 没有因为项目层重复项被忽略而消失；

它补充了重要限定：没有运行通知触发实验，因此只能说“没有配置层证据表明 Orca 丢失通知”，不能说“通知功能已经端到端验证正常”。

## 成本与可观察性

完整报告结束时，TUI 显示：

- 481K 累计输入；
- 5.1K 输出；
- 约 26% 上下文使用；
- `86.1K used`；
- 周额度从头到尾显示 96% 剩余。

这些是 TUI 显示值，不等同于已核验的账单 token。累计输入很高，主要来自高推理档位、多次官方文档搜索和工具结果回填。

Orca 原生终端明显改善了上次完全不可见的问题：当前 Session 能看到阶段、计划、工具调用、失败恢复和最终报告。但原始 TUI 增量输出包含大量重绘噪声，需要当前 Session 解释；持续轮询也仍有协调成本。

## ROI 结论

1. Orca TUI 可以作为需要监督、阶段门或故障可观察性的跨 Session 路径；
2. 对这类很小且已有结论的任务，`xhigh` 加多次网页搜索成本过高；
3. 当前不应马上建设自动调度或完整监控；
4. 下一次应附着在自然出现的真实任务上复用，并优先减少重复调研、降低推理档位或限定官方资料入口；
5. 原始 TUI 保留在 Orca 中供人阅读，没有自动关闭。
