# 发布与观测

改动做好后怎么放出去、放出去后看什么。这是 ISO 12207 的 6.4.10 移交与 6.4.12 运行在 workCoding 里合成的一条规程。无配套标准；ISO/IEC 20000 的变更与发布管理是最近的亲戚。前提事实：`遗留代码修改.md` 第 4 步的分流开关就是灰度开关——绞杀者按请求类别分流，灰度就是逐步放大这个类别——所以发布方案是分流开关的放量计划，不另起炉灶。

## 规程，五步

| 步 | 做什么 | 槽位里的实践 |
|---|---|---|
| 1 定放量顺序 | 开关初始关。档 1 只放内部账号或测试模板；档 2 放分流类别的一小部分；档 3 全量。每档写清「放谁」「停多久」 | 特性开关 Feature Toggle（Hodgson / Fowler）；金丝雀发布 Canary Release |
| 2 定回滚点 | 每档的回滚动作都是「关开关」，不回滚代码。可行的前提是老代码 diff 为零：关了开关就是发布前 | 开关回滚；绞杀者 Strangler Fig |
| 3 定观测点 | `需求翻译.md` 的每条 EARS 句配一个观测：新路径命中数、抽样结果与例子一致、新路径异常数。老路径看四个黄金信号不变：延迟、流量、错误、饱和 | Google SRE 四个黄金信号 |
| 4 演示 | 档 1 放开后，用需求翻译第 3 步的例子在线上打一遍，与期望输出比对。即 12207 产出「能力已在运行环境演示」 | 冒烟测试 Smoke Test |
| 5 留 | 放量顺序、回滚点、观测点进本库工作语境笔记「发布与观测实例」；每档观测结果进 PR 或工单 | ADR 归档 |

## 产物样例

```
改动：偏远附加按省份查表（分流条件：模板配置了偏远省份表）
放量：档 1 测试模板 9001，半天 ｜ 档 2 模板 id 末位为 7，一天 ｜ 档 3 全量
回滚：任一档异常，关 remote_fee_by_province 开关
观测：新路径命中数 ｜ 抽 20 条比对例子 ｜ 新路径异常数 = 0 ｜ 老路径 p99 延迟、错误率不变
演示：档 1 放开后用 模板 1032 新疆 3.2kg 打一条，期望 26
```

## 6.4.12 在灰度之外的部分

发布后日常盯日志与告警，发现问题转成一个维护改动，进 Feathers 流程第 1 步。一句话即全部，不另设规程。

## 备选与不选理由

- 第 1 步：蓝绿部署。不选：它切整个实例，切不了「某类请求」；且是否可用取决于雇主基建。
- 第 3 步：SLI/SLO 与错误预算。不选：单个改动的灰度期用不上预算，四个信号够；SLO 属于 6.4.12 的长期形态，需要时再引入。

## 依赖

雇主的开关系统与放量手段由开发环境盘点回答（`开发环境盘点.md`）：有配置中心型开关与带类型开关，放量支持百分比与黑白名单 → 放量三档定为白名单 → 百分比 → 全量，回滚 = 关开关。运行时诊断工具任何环境可用，第 3 步的观测可直接核。
