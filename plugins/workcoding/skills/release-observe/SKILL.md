# 发布与观测：放量三档，回滚即关开关，一句一观测

改动做好后怎么放出去、放出去后看什么。这是 ISO 12207 的 6.4.10 移交与 6.4.12 运行在 workCoding 里合成的一条规程。无配套标准；ISO/IEC 20000 的变更与发布管理是最近的亲戚。前提事实：`legacy-change` 工位 4 的分流开关就是灰度开关——绞杀者按请求类别分流，灰度就是逐步放大这个类别——所以发布方案是分流开关的放量计划，不另起炉灶。

真源在个人知识库 `notes/发布与观测.md`（与标准的对照、备选与不选理由、依赖、裁决史、未解决）；步骤在本文。

## 为什么需要它

没有发布方案的改动通常是「合了就上」，出事时回滚代码要重新构建部署，期间新老都不在；有了分流开关但没定观测点的改动，放出去之后没人知道新路径命中了几条、算对了没有，等商家投诉才知道。所以发布方案只做四件事：开关怎么放大、出事关哪个开关、每条需求句看什么、第一档放开后拿例子打一条。

## 三条铁律

1. **回滚点就是关开关，不回滚代码。**
   可行的前提是老可执行路径 diff 为零：关了开关就是发布前。没有这个前提就先回 `legacy-change` 工位 5 静态验。
   理由：回滚代码要重新构建部署，窗口期新老都不在；关开关是秒级且可逆。
2. **每条需求句配一个观测点，写不出观测点的句子不放。**
   新路径看：命中数、抽样结果与例子一致、异常数。老路径看四个黄金信号不变：延迟、流量、错误、饱和。
   理由：观测点是需求句在线上的样子；写不出就不知道放出去之后看什么。
3. **每档放量与进下一档由主人裁定，agent 不开开关。**
   理由：放量是不可逆的外发动作，主人固定出手的点之一。

纠偏留痕：主人否了放量档位或观测点，原话记在被否那行下面，不覆盖。

## 五个工位

| 工位 | 干什么 | 槽位里的实践 |
|---|---|---|
| **1 定放量顺序** | 开关初始关。档 1 只放内部账号或测试模板；档 2 放分流类别的一小部分；档 3 全量。每档写清「放谁」「停多久」 | 特性开关 Feature Toggle（Hodgson / Fowler）；金丝雀发布 Canary Release |
| **2 定回滚点** | 每档的回滚动作都是「关开关」，不回滚代码 | 开关回滚；绞杀者 Strangler Fig |
| **3 定观测点** | `requirement-translation` 的每条 EARS 句配一个观测：新路径命中数、抽样结果与例子一致、新路径异常数。老路径看四个黄金信号不变 | Google SRE 四个黄金信号 |
| **4 演示** | 档 1 放开后，用需求翻译工位 3 的例子在线上打一遍，与期望输出比对。即 12207 产出「能力已在运行环境演示」 | 冒烟测试 Smoke Test |
| **5 留** | 放量顺序、回滚点、观测点进工作语境笔记「发布与观测实例」与改动记录「方案」一节；每档观测结果进 PR 或工单 | 改动记录 |

工位 1–3 一次出完给主人否；工位 4 在档 1 放开后做；每档的开关操作与是否进下一档，主人裁定。

雇主环境（`notes/开发环境盘点.md`）：有配置中心型开关与带类型开关，放量支持百分比与黑白名单，所以三档定为白名单 → 百分比 → 全量。没有开关系统的环境（vibeCoding、示范）：配置项或环境变量当开关，放量退化为「开 / 关」两档（2026-09-02 预演发现 5，待主人裁定，用到时标假设）。

## 产出：一段发布方案，没有别的

```
改动｜<一句>（分流条件：<看入参哪个字段>；开关：<名>）
放量｜档 1 <放谁>，停 <多久> ｜ 档 2 <放谁>，停 <多久> ｜ 档 3 全量
回滚｜任一档异常，关 <开关名>；前提：老路径 diff 为零已静态验
观测｜<需求句 1> → <观测点> ｜ <需求句 2> → <观测点> ｜ … ｜ 老路径：p99 延迟、流量、错误率、饱和不变
演示｜档 1 放开后用 <例子> 打一条，期望 <输出>
请裁定档 1 放谁；每档放开和进下一档我都等你。
```

例子：

```
改动｜偏远附加按省份查表（分流条件：模板配置了偏远省份表；开关：remote_fee_by_province）
放量｜档 1 测试模板 9001，停半天 ｜ 档 2 模板 id 末位为 7，停一天 ｜ 档 3 全量
回滚｜任一档异常，关 remote_fee_by_province；前提：calc 老路径 diff 为零已静态验
观测｜「省份在表中时加附加」→ 新路径命中数、抽 20 条比对例子 ｜「不在表中不加」→ 新路径异常数 = 0 ｜ 老路径：p99 延迟、错误率不变
演示｜档 1 放开后用模板 1032 新疆 3.2kg 打一条，期望 26
请裁定档 1 放谁；每档放开和进下一档我都等你。
```

**主人裁定之前：不开开关、不改配置、不发公告。**

## 6.4.12 在灰度之外的部分

发布后日常盯日志与告警，发现问题转成一个维护改动，进 `legacy-change` 工位 1。一句话即全部，不另设规程。

## 路由边界

| 相邻 | 它管什么 | 分界（可测） |
|---|---|---|
| **`integration`** | 接入顺序、预发联调 | 它的顺序到「预发联调」为止；预发过了才轮到本 skill |
| **`legacy-change`** | 改代码 | 分流开关在它工位 4 建；本 skill 只放大它，不新造开关 |
| **`evidence-regression`** | 证明老流程没变 | 它是改代码前后的仓内母版回放；本 skill 工位 3、4 是线上抽样比对，两码事 |
| **`requirement-translation`** | 需求句与例子 | 本 skill 的观测点一句一个、演示用它的例子；不在这里改句子 |
| 蓝绿部署、SLO 与错误预算 | 备选，不选 | 蓝绿切整个实例切不了某类请求；SLO 是 6.4.12 的长期形态（见真源笔记） |

## 边界

- 只回答「放多少、出事关什么、看什么、打哪条」，不回答「怎么接进去」和「代码怎么改」。
- 不做 SLO、错误预算、告警体系设计；单个改动的灰度期用四个信号够。

## 自检（任一条破了就是失败）

- [ ] 三档各写了放谁、停多久
- [ ] 回滚写的是关哪个开关，并写了「老路径 diff 为零」这个前提
- [ ] 每条需求句都有一个观测点，老路径列了四个信号
- [ ] 演示用的是需求翻译的例子，写了期望输出
- [ ] 主人裁定之前没开开关
