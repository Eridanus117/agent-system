# 遗留代码修改

agent 改一段注释与实现对不上、圈复杂度上百的代码时，先带一条真实请求走读并摆出现状，人否掉之后再以「新增不改、入口分流」的方式动手。这套走法不是自创，逐步对应 Michael Feathers《修改代码的艺术》（Working Effectively with Legacy Code, 2004）的遗留代码修改算法，外挂 ADR 与 IEEE 1028 走查；外层形态是绞杀者 Strangler Fig。

## 六步

| 步 | 做什么 | 业界名 |
|---|---|---|
| 1 走读 | 拿一份真实入参沿代码走一遍，写出经过哪些分支、每个分支看入参的哪个字段、注释与实现对不上的地方。以走读为准，注释不算数 | Feathers 第 1、2 步「确定改动点、找测试点」；产物是特征化测试 Characterization Test |
| 2 摆改法 | 整句写三件事：新逻辑放在哪个新入口；哪种请求走新入口、用入参哪个字段判断；其余请求照旧 | ADR（Nygard 2011），Y 语句形态 |
| 3 人否 | 人看第 1、2 步，错了说「不是这样，是……」。agent 把原话记在走读下面，重走，不覆盖旧版 | IEEE 1028 走查 walkthrough |
| 4 建 | 新代码只新增文件或方法；老代码 diff 为零；分流判断只写在入口一处 | Feathers 第 3 步「解依赖」：萌芽方法 Sprout Method / 萌芽类；接缝 Seam + 特性开关 |
| 5 静态验 | 老文件 diff 为零；静态分析确认老代码未引用新代码；分流判断配一条测试，用第 1 步那条入参当用例 | Feathers 第 4 步「写测试」；静态分析 |
| 6 留 | 第 1、2 步原文与人的纠偏原话一起进 PR 正文，不建文档 | ADR 归档 |

对 agent 说「按 Feathers 走」即指这六步。

## 走读产物的形态（2026-09-02 裁定）

同一条请求的执行轨迹有三种呈现：文字清单、特征化测试、时序图。它们不是三个选项，是同一份内容的三种视图，按「存储唯一、视图随意」处理：

- **特征化测试是存储**：进仓库，能跑；跑不过说明走读编了。每个 `expect` 带一行中文注释，注释即走读的一步。
- **文字清单是 agent 摆给人看的那一面**：就是测试里的注释逐行抄出，不另写、不另存。人否的是注释，agent 改的是测试。
- **时序图不存**：十步以内清晰，上百分支时比清单还长；要看时现画。

清单一步的写法：「看 <入参字段> = <值> → <进/跳过哪个分支> → <数值变化>（<注释与实现的出入>）」。

## 摆现状时的硬约束

- 摆的每一句必须能对照人手上的具体对象（那条入参、那个文件）判对错；不用占位符（X、Z）、自造词、流程代号。判据是同一语境，不是长度。
- 拿不出证据的一行不许写成断言，只能写成「假设」；人先否假设。
- 「旧路径不动」是默认，不写；写的是分流条件。
