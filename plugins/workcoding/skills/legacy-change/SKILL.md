# 遗留代码修改：先走读，人否，再萌芽

agent 改一段注释与实现对不上、圈复杂度上百的代码时，先带一条真实请求走读并摆出现状，人否掉之后再以「新增不改、入口分流」的方式动手。这套走法不是自创，逐步对应 Michael Feathers《修改代码的艺术》（Working Effectively with Legacy Code, 2004）的遗留代码修改算法，外挂 ADR 与 IEEE 1028 走查；外层形态是绞杀者 Strangler Fig。对 agent 说「按 Feathers 走」即指这六步。

真源在个人知识库 `notes/遗留代码修改.md`（与 Feathers 的对照、裁决史、未解决）；步骤在本文。

## 适用边界

本规程是一种已选择的修改策略，不是所有既有代码改动的默认做法。进入前确认确有复杂遗留行为需要锁定，并且新旧路径并存符合本次目标；简单原地修复无需为使用本 skill 制造新入口、开关或旧接口兼容层。已经确认的输入、走读与改法直接复用，只询问新缺口。

## 为什么需要它

agent 改代码最贵的错不是写错，是**理解错了现状还写得很顺**：注释说 vip 免续重，实现是打五折；agent 信了注释，改法从第一句就错，而人在它动手前无从判断它理解得对不对。解法是把理解摆出来给人否——用一条真实入参走一遍，每一步写「看哪个字段、进哪个分支、数怎么变」，人对着自己的请求能一眼判对错。选定新旧并存策略后，保留旧业务实现、在确认的入口增加一处分流；用关闭开关后的行为验证回到原路径，而不是用整份文件零 diff 代替回滚证据。

## 三条铁律

1. **以走读为准，注释不算数；走读的每一步都能对照那条入参判对错。**
   清单一步的写法：「看 <入参字段> = <值> → <进/跳过哪个分支> → <数值变化>（<注释与实现的出入>）」。不用占位符、自造词、流程代号。
   理由：主人说「看不懂」，是 agent 没和主人站在同一条请求上，不是嫌长。
2. **拿不出证据的一行写「假设」；走读与改法确认前不改生产实现。** 在任务允许写测试时，可先用隔离的特征化测试核实现状；未获写入授权时只读并说明证据边界。
   理由：改法建立在走读上，走读错了改法全错；人先否假设。否三次还不对就停下拆（6.3.2 的规矩）。
3. **旧业务实现保持不变，新逻辑独立新增；入口分流是唯一允许的既有代码修改。**
   明确列出这处分流的路径、条件与关闭后的去向；不能把整份旧文件零 diff 与修改同一文件入口同时当作验收条件。
   关闭开关须经行为验证回到原路径；diff 小或为零本身不证明回滚正确。

纠偏留痕：主人否了走读或改法，原话记在被否那段下面，重走，不覆盖旧版。

## 六个工位

| 工位 | 干什么 | 业界名 |
|---|---|---|
| **1 走读** | 拿一份真实入参沿代码走一遍，写出经过哪些分支、每个分支看入参的哪个字段、注释与实现对不上的地方 | Feathers 第 1、2 步「确定改动点、找测试点」；产物是特征化测试 Characterization Test |
| **2 摆改法** | 说明新入口、分流开关和请求条件；开关开启且命中目标请求才走新入口，开关关闭时所有请求回原入口。开关的来源或控制权限不明时列为待确认，不擅自造一个生产开关 | ADR（Nygard 2011），Y 语句形态 |
| **3 人否** | 人看第 1、2 步，错了说「不是这样，是……」。agent 把原话记在走读下面，重走 | IEEE 1028 走查 walkthrough |
| **4 建** | 新增文件或方法承载新逻辑；保留旧业务实现，只在已确认入口添加一处分流。分流须先于可能吞掉新请求的兜底分支，位置以真实调用链为准 | 萌芽方法 Sprout Method / 萌芽类；接缝 Seam + 特性开关 |
| **5 验证** | 核对既有代码修改仅含已确认入口分流；旧实现内部没有新增依赖。用同一批可观察输入验证关闭开关走原行为、打开开关仅改变目标类别；接口扩展纳入实际接入边界 | 特征化测试、行为回归与静态分析 |
| **6 留** | 第 1、2 步原文与人的纠偏原话一起进改动记录「方案」与「做」两节（PR 正文），不建文档 | 改动记录 |

工位 1、2 一次出完给主人，工位 3 等主人，4–6 在主人否过之后。工位 2 卡住（不知道有没有绕过入口的调用方、不知道新路径慢多少）就起 `system-analysis` 一次，结论回到改法里。

## 走读产物的形态（2026-09-02 决定）

同一条请求的执行轨迹有三种呈现：文字清单、特征化测试、时序图。它们不是三个选项，是同一份内容的三种视图，按「存储唯一、视图随意」处理：

- **特征化测试是存储**：进仓库，能跑；跑不过说明走读编了。每个 `expect` 带一行中文注释，注释即走读的一步。
- **文字清单是 agent 摆给人看的那一面**：就是测试里的注释逐行抄出，不另写、不另存。人否的是注释，agent 改的是测试。
- **时序图不存**：十步以内清晰，上百分支时比清单还长；要看时现画。

## 产出：走读清单加改法三句，没有别的

```
入参｜<那条真实请求的关键字段>
走读｜
  1 看 <字段> = <值> → <进/跳过哪个分支> → <数值变化>（<注释与实现的出入>）
  2 …
  结果｜<老代码对这条入参的输出>
假设｜<拿不出证据的那几行>
改法｜新逻辑放在 <新入口>；<已约定开关> 开启且 <请求条件>（看入参 <字段>）时走新入口；开关关闭或请求未命中时走 <原入口>
请否走读和改法；哪一步不对写在那步下面，我重走。
```

例子：

```
入参｜模板 1032，目的地新疆，3.2kg，vip=false
走读｜
  1 看 weight = 3.2 → 进续重分支 → 18 + 3 × 4 = 30（注释写「按 0.5kg 进位」，实现是向上取整到 1kg）
  2 看 vip = false → 跳过 vip 分支 → 30 不变（注释写「vip 免续重」，实现是续重打五折，本条未触发）
  3 看 region = 西北 → 进区域加价 → 30 + 3 = 33
  结果｜33
假设｜区域加价表是否含「新疆」单独一行，代码里看不出，待核
改法｜新逻辑放在 calcRemoteFee；已约定的 remoteFeeEnabled 开启且省份在偏远省份表（看 province）时走新入口；开关关闭或省份未命中时走原计费入口
请否走读和改法；哪一步不对写在那步下面，我重走。
```

**走读与改法确认前：不改生产实现、不建实施分支；隔离特征化测试的权限见上文。**

## 路由边界

| 相邻 | 它管什么 | 分界（可测） |
|---|---|---|
| **`workcoding`** | 判形状、摆路线 | 路线确认之前是它；本 skill 不摆路线 |
| **`system-analysis`** | 一个决定缺一个数 | 工位 2 卡住时起它一次，结论回改法；本 skill 不画全量调用图 |
| **`integration`** | 接进系统 | 工位 4 建完之后是它；集成面、接入顺序不在这里 |
| **`evidence-regression`** | 证明老流程没变 | 特征化测试锁一条入参；母版回放锁一批。改代码前采母版是它的事 |
| **`release-observe`** | 放出去 | 工位 4 的分流开关就是灰度开关；放量与回滚点在它那里 |
| 从零新建、纯新增文件 | 暂无规程 | **对象没有既有可执行路径要动 → 不是本 skill**。PR #33 纠偏：新增文件写「萌芽改法」是套词 |

## 边界

- 只处理「改一段既有代码」；对象是文档、规则、脚本新建的不进来。
- 不讲解 Feathers 方法本身；问「接缝是什么」直接答。

## 自检（任一条破了就是失败）

- [ ] 走读每一步写了看哪个字段、进哪个分支、数怎么变；没有占位符
- [ ] 注释与实现的出入单独标出，没有信注释
- [ ] 拿不出证据的行写了「假设」
- [ ] 改法是整句的三件事，写的是分流条件而不是「旧路径不动」
- [ ] 改生产实现前已确认走读与改法；旧业务实现未改，入口分流只有一处且关闭后的旧行为已验证
