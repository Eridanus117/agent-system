# 集成：列边界，写变没变，定顺序，联调

改动做完后把它接进整个系统。ISO 12207 的 6.4.8 要的产出：集成策略已定、对设计的约束已明、元素已接上、接口已检查、结果已记录。对改既有系统的人，「接进去」碰的边界有五种：上游调用方、下游依赖（表、配置、外部服务）、开关注册、数据变更、别人同时在改的代码。最后一种归 6.3.5 配置管理（合分支解冲突），不在本规程里。无配套标准。

真源在个人知识库 `notes/集成.md`（与标准的对照、与其他规程的咬合、备选与不选理由、裁决史、未解决）；步骤在本文。

## 为什么需要它

`legacy-change` 的特征化测试证明的是「这一个方法对这一条入参没变」，证明不了整条链：上游谁调、下游那张表加了列之后旧读法还对不对、开关注册了没有、先合代码还是先加列。这些边界没有一处在单元测试里，漏一个就是线上事故，而且事故发生时已经没有单步可退的位置。所以先把边界列全、每个写变没变、排一个每步能单独退的顺序，再沿真实调用链跑一遍需求翻译的例子。

## 三条铁律

1. **每个边界都要写「变没变」，没变的写「不变」，不留空。**
   变了的写清变了什么、谁要知道：签名、语义、异常、幂等。
   理由：「不变」是萌芽方法的承诺（新入口签名与老的一致），写出来才有人核；空着等于没查。
2. **顺序里每一步都能单独退；退不了的一步就拆成能退的两步。**
   依赖在前：表与配置先扩不收 → 开关注册且关着 → 代码合入 → 下游 → 上游。数据变更先扩后缩，新旧并存一段再删旧。
   理由：一次性大爆炸集成不能单步退，出事只能整体回滚。
3. **联调沿真实调用链跑需求翻译的例子，再跑一条老路径的例子；共库时只读。**
   理由：单元级特征化测试证明不了整条链；预发与生产共库时写操作会污染生产数据。

纠偏留痕：主人否了集成面或顺序，原话记在被否那行下面，不覆盖。

## 五个工位

| 工位 | 干什么 | 槽位里的实践 |
|---|---|---|
| **1 列集成面** | 列出改动碰到的每个边界：谁调我、我调谁、动了哪张表哪个配置、注册了什么开关。来源：`system-analysis` 的影响草图、工作语境笔记「系统地图」 | 12207 集成策略 |
| **2 每个边界写「变没变」** | 变了的写清变了什么、谁要知道：签名、语义、异常、幂等。没变的写「不变」。类型或接口只增不改的扩展也算「变了」，要列 | 接口契约检查清单 |
| **3 定接入顺序** | 依赖在前、每步可单独退：表与配置先扩不收 → 开关注册且关着 → 代码合入 → 下游 → 上游 | 增量集成 Incremental Integration；扩展收缩 Expand/Contract（Fowler 并行修改 Parallel Change） |
| **4 联调** | 在测试或预发环境沿真实调用链跑 `requirement-translation` 的例子，再跑一条「老路径不受影响」的例子。共库只读 | 集成测试；例子复用 |
| **5 留** | 集成面清单与接入顺序进改动记录「做」一节（PR 正文）；新发现的边界进工作语境笔记「系统地图」 | 改动记录；「系统地图」 |

工位 1–3 一次出完给主人否；工位 2 的「谁要知道」由主人去通知；工位 4 在预发由主人或按授意执行。

## 产出：一段集成清单，没有别的

```
集成面｜上游 <谁调我> ｜ 下游 <我调谁：表、配置、外部服务> ｜ 开关 <名>
变没变｜<边界>：<不变 / 变了什么，谁要知道>（每个边界一条）
顺序｜1 <表或配置扩> → 2 <开关注册，关> → 3 <合代码> → 4 <下游> → 5 <上游>；每步退法：<一句>
联调｜<需求翻译的哪条例子沿哪条链跑，期望什么>；老路径：<哪条例子，期望不变>；<共库只读 / 可写>
请否集成面和顺序；漏了哪个边界、哪步退不了直接说。
```

例子：

```
集成面｜上游 OrderService、QuoteService、BatchCalc ｜ 下游 remote_fee 表、模板配置 ｜ 开关 remote_fee_by_province
变没变｜calc 签名：不变 ｜ calcInner：新增一个重载，老重载不动，BatchCalc 要知道 ｜ remote_fee 表：新增 province 列，旧列保留，报表任务要知道 ｜ 模板配置：新增偏远省份表字段，未配置即不加
顺序｜1 remote_fee 加列（退：列留着不用）→ 2 注册开关，关（退：删注册）→ 3 合代码（退：开关关着即老路径）→ 4 预发联调 → 5 灰度见 release-observe
联调｜模板 1032 新疆 3.2kg 走 OrderService 全链，期望 26；老路径：模板 2001 广东走 BatchCalc，期望不变；预发与生产共库，只读
请否集成面和顺序；漏了哪个边界、哪步退不了直接说。
```

**主人否过之前：不合分支、不动表、不注册开关。**

## 路由边界

| 相邻 | 它管什么 | 分界（可测） |
|---|---|---|
| **`legacy-change`** | 改代码 | 它的工位 4 建完之后才轮到本 skill；改法、走读不在这里 |
| **`system-analysis`** | 一个决定缺一个数 | 它的影响草图喂本 skill 的集成面；本 skill 不自己画草图 |
| **`release-observe`** | 放出去 | 本 skill 的顺序到「预发联调」为止；放量三档、回滚点、观测点在它那里 |
| **`evidence-regression`** | 证明老流程没变 | 母版回放是仓内测试；本 skill 的联调是预发真实链路，两码事 |
| 合分支解冲突 | 6.3.5 配置管理 | 别人同时在改的代码 → 不在本 skill |

## 边界

- 只回答「接进去碰哪些边界、什么顺序、联调跑什么」，不回答「代码怎么改」和「放量放多少」。
- 消费者驱动契约测试（Pact）不在这里：上下游都要接工具，单人推不动，先用清单（见真源笔记）。

## 自检（任一条破了就是失败）

- [ ] 五种边界逐个过了：上游、下游、开关、数据、别人的代码（最后一种标「归配置管理」）
- [ ] 每个边界都写了变没变，没有空着的
- [ ] 顺序每步写了退法，没有退不了的一步
- [ ] 联调跑的是需求翻译的例子加一条老路径例子，共库时标了只读
- [ ] 主人否过之前没合分支、没动表

## 验证状态

**首版未验证。** 2026-09-02 只在隔离环境跑过单轮 behavior case（见 `evals/`），测到的是集成清单形态、变没变逐边界、顺序带退法与停住；预发联调本身在对话里跑不了。真正的判据是在工作机上接一条真实改动走一遍，顺序里有没有哪一步实际退不了。
