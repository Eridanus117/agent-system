# 集成

改动做完后把它接进整个系统。ISO 12207 的 6.4.8 要的产出：集成策略已定、对设计的约束已明、元素已接上、接口已检查、结果已记录。对改既有系统的人，「接进去」碰的边界有五种：上游调用方、下游依赖（表、配置、外部服务）、开关注册、数据变更、别人同时在改的代码。最后一种归 6.3.5 配置管理（合分支解冲突），不在本规程里。无配套标准。

## 规程，五步

| 步 | 做什么 | 槽位里的实践 |
|---|---|---|
| 1 列集成面 | 列出改动碰到的每个边界：谁调我、我调谁、动了哪张表哪个配置、注册了什么开关。来源：`系统分析.md` 的影响草图、本库「系统地图」 | 12207 集成策略 |
| 2 每个边界写「变没变」 | 变了的写清变了什么、谁要知道：签名、语义、异常、幂等。没变的写「不变」——这是萌芽方法的承诺，新入口签名与老的一致 | 接口契约检查清单 |
| 3 定接入顺序 | 依赖在前、每步可单独退：表与配置先扩不收 → 开关注册且关着 → 代码合入 → 下游 → 上游。数据变更先扩后缩，新旧并存一段再删旧 | 增量集成 Incremental Integration；扩展收缩 Expand/Contract（Fowler 并行修改 Parallel Change） |
| 4 联调 | 在测试或预发环境沿真实调用链跑 `需求翻译.md` 的例子，再跑一条「老路径不受影响」的例子。单元级特征化测试证明不了整条链 | 集成测试；例子复用 |
| 5 留 | 集成面清单与接入顺序进 PR 正文；新发现的边界进本库工作语境笔记「系统地图」 | ADR；本库「系统地图」 |

## 产物样例

```
集成面：上游 OrderService、QuoteService、BatchCalc ｜ 下游 remote_fee 表、模板配置 ｜ 开关 remote_fee_by_province
变没变：calc 签名不变；calcInner 新增一个重载，老重载不动；remote_fee 表新增 province 列，旧列保留
顺序：1 加列 → 2 注册开关（关） → 3 合代码 → 4 预发联调 → 5 灰度见发布与观测
联调：模板 1032 新疆 3.2kg 走 OrderService 全链，期望 26；模板 2001 广东走 BatchCalc，期望不变
```

## 与其他规程的咬合

第 1 步吃 `系统分析.md` 的草图；第 4 步吃 `需求翻译.md` 的例子；第 5 步喂 `发布与观测.md` 的放量。

## 备选与不选理由

- 消费者驱动契约测试（Pact 一类）。不选：要上下游都接工具，单人推不动；先用清单。
- 一次性大爆炸集成。不选：不能单步退。
