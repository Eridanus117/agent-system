# 把念头变成判断

主人的痒点**永远以「解」的形式出现**——冒出来的是「我想建个 X」，不是「我有个问题 P」。而 X 已经预设了问题是什么、这是最好的解法、值得做。

本 Skill 的全部工作：**把 X 翻回问题，再判断该不该解。**

## 为什么需要它

主人试过 spec-kit、OpenSpec、BMad 和自建 OpenSpec 改造版，四个全部失败。根因是同一个：**那些工具都是产出方，第一句都是「描述你要构建的东西」——要求人先说清楚。而主人的困难恰恰是说不清楚。**

把念头变成判断，靠的是**被问**，不是靠说。所以这里 agent 是提问方，不是产出方。

对应事项 **E5（想清楚一件事）**。该事项此前由 `bmad` 组覆盖，`bmad` 于 2026-09-01 删除后由本组接手。

## 三条铁律

1. **给断言，不给问句。**
   写「这个仓是 X」，不写「你觉得这个仓是什么」。
   理由：主人对「这句不对」的判断，比对「你想要什么」的回答**快十倍也准十倍**。问开放题会得到「我的认知有点不太够」。
2. **草案短到能一眼判错。**
   长了主人的反应是「看不懂」——那不是纠偏，是失联。一次只摆一屏。
3. **纠偏本身要留痕**：记「我说 A，主人说不是，是 B」，不是只留最新版。
   被否掉的路径才是三个月后看得懂的那部分。

## 四个工位（不是问卷，别照念）

问题必须**针对当下这个痒点现生成**。固化成模板五问，主人会越答越敷衍——有先例：某流水线五个站位的推进时间戳是 0.5～1.0 秒内连点五下。

| 工位 | 干什么 | 用什么 |
|---|---|---|
| **1. 把解翻回问题** | 找出真正卡住的是什么 | JTBD 切换访谈（**问历史行为**：上次撞到时你怎么办的？现在怎么忍过来的？——不问意见，历史能回忆，意见会现编）＋ 5 Whys |
| **2. 泼冷水** | 找出这事会怎么砸 | Pre-mortem：假设半年后彻底失败了，回头看为什么。列 4–5 条，**按可信度排**，优先采信有历史证据的那几条 |
| **3. 查现成的** | 该不该自己做 | 竞品 / buy-vs-build 调研，**agent 代跑**，主人零成本 |
| **4. 收口** | 出结论 | 问题陈述 |

**贯穿全程的载体**：agent 写断言式草案 → 主人纠偏 → 重复到主人不想改了。

## 产出：三行，没有别的

```
1｜真正的问题：不是「<痒点原话>」，而是 <翻译后的问题>
2｜值不值得解：<值得/不值得/先不解> —— <理由，含发生频率与已付代价>
3｜往哪个方向解：<方向> —— <排除掉的方向及原因>
```

**不产出文件、不开 change、不列 task、不建目录。** 三行说完就结束。
需要留痕时才落盘，落在痒点原本所在的地方（intake 条目、desk 提案），不新造容器。

## 路由边界

| 相邻 | 它管什么 | 分界（可测） |
|---|---|---|
| **`grilling`** | 用结构化问题压力测试**已经成型的**计划、决定或想法 | **触发条件正相反**：grilling 必须显式请求且对象已成型；clarify 自动触发且对象是还没成型的念头 |
| **`adaptive-problem-solving`** | 执行**途中**的含糊、停滞、里程碑、交接、验收；恢复原问题与主瓶颈 | **时机**：APS 在任务已经开跑之后；clarify 在还没有任务的时候 |
| **`self-improvement`** | Agent 漂移、误解、重复犯错，把经验固化为系统改进 | 对象是 agent 自己，不是待办的事 |
| **`knowledge-maintenance`** / `note` | 沉淀已有结论 | 那是**产生结论之后**的动作；clarify 负责产生结论 |

## 边界

- 只覆盖「我想建个 X」这一类痒点。「这个 bug 烦我」这种别硬套。
- 只回答「该不该做」，**不回答「做成什么样」**——那是下一段的事，别把它的债记在这里。

## 为什么形态是 Skill，不是别的

2026-09-01 比较过五种形态，判据是 Pre-mortem 给出的两条硬约束：**发起必须零成本**（不得有命令名，防「走过一次再无第二次」）与**不得常驻**（防挤占上下文）。

| 形态 | 零成本发起 | 常驻开销 | 能否强制 | 结论 |
|---|---|---|---|---|
| **Skill** | ✅ description 自动匹配 | 只占一行 description | ❌ | **选中**——唯一同时满足前两条 |
| 全局 `CLAUDE.md` 规则 | ✅ 永远在 | ❌ 全文常驻，稀释既有规则 | 弱 | 否 |
| subagent / agent 定义 | ❌ 需显式调用 | — | ❌ | 否，破第一条 |
| hook | ❌ **拦不住自然语言**——痒点是自由文本，无锚点 | — | ✅ | 否 |
| output style | ✅ | ❌ 全文常驻 | — | 否，太重 |
