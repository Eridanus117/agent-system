# 机会 issue

第 5 步「建」那条出口的产物，建在 desk 仓（念头出现时目标仓可能还不存在，desk 是念头与跨仓决策的家），挂到所属主题下。标题是三行里第 1 行的问题，代替念头原话。标签留给 tracker 自己的词表，本 skill 不定。

## 正文四节

```
## 念头原话
<主人的那一句>

## 需要解
<第 1 行：真正的问题，带名字>

## 价值已立
<第 2 行：值不值得解，含频率与代价>

## 可行
<第 3 行：往哪个方向解，沿用什么、排除什么>

## 出口
目标仓需求 issue 的回链（仓还没有先空着）

确认：<日期> 主人对三行的划改
```

## 命令

```
gh issue create -R <owner>/desk --title "<第 1 行的问题>" --body-file <正文文件> --parent <主题 issue 的 URL>
```

不建或先不解的那条：同一命令建完，再 `gh issue close <编号> -R <owner>/desk --reason "not planned"`；标签 `wontfix` 由 tracker 的词表定。
