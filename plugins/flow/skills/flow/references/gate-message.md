# 门上那条消息

三部分的顺序与要求见 `flow` 正文「门上那条消息」；这里只放模板与例子。

## 模板

```
这是第 N 阶段〈阶段名〉。门上判：〈九个阶段那张表里门那一栏〉。
〈这个阶段的产物或准备：一到五条〉
〈请敲 /名 ｜ 说「行」就进第 N+1 阶段〉
```

## 例子一：第 2 阶段入口

```
这是第 2 阶段方案对齐。门上判：每轮判对错、确认接缝、收 ADR。
已绑 issue 27，最后一条站会记录的下一步是「主人敲 /grill-with-docs」。
请敲 /grill-with-docs。
```

## 例子二：第 4 阶段的门，改没有测试的旧代码

```
这是第 4 阶段开工准备。门上判：开哪些改旧代码时才开的活动、基线过没过。
- worktree：desk31-streaming-importer，分支从 main 出，已绑 issue 31
- 基线：仓自己的检查跑过一遍（现在一个测试都没有，基线就是「没有测试」）
- 这次开的改旧代码时才开的活动：legacy-change（先录旧行为：六处脏数据处理各写一条特征化测试）、regression-evidence（改前改后导入结果逐字节比）；理由：旧代码没有测试，验收要求逐字节一致
说「行」就录旧行为，录完请敲 /implement 进第 5 阶段。
```

从零新建的那一行写「从零新建，不开改旧代码的活动」。
