# 方法资产的符合性检查

## 人话结论

来源正确、文件格式正确、能够安装、行为符合合同、方法值得使用，是五件不同的事。前一项通过不能自动证明后一项。

本文只定义后续需要什么证据，不保存某次试验日志，也不宣称 `grilling` 已经通过任何运行端验证。资产对象和责任的唯一正文在[方法资产模型](asset-model.md)。

## 证据层级

| 证据层级 | 需要的证据 | 通过能说明什么 | 仍然不能说明什么 |
| --- | --- | --- | --- |
| 来源与许可证 | 固定的上游提交、文件哈希、许可证文本和逐项本地修改 | 纳入内容可追溯，许可材料完整 | 本地修改正确，或方法值得使用 |
| Agent Skills 公共格式 | `SKILL.md` 必需字段、相对引用和公共格式检查 | 共同 Skill 满足公共文件合同 | Codex 或 Claude 的 Plugin 一定能安装 |
| Codex 包装与安装 | Codex 清单和路径检查、发现、安装、版本与缓存比对 | 当前 Codex 版本能解析并安装所选包 | Claude 兼容，或用户行为符合产品合同 |
| Claude 包装与安装 | Claude 原生校验、发现、安装、版本与缓存比对 | 当前 Claude 版本能解析并安装所选包 | Codex 兼容，或方法产生收益 |
| 生命周期 | 安装前状态、启用版本、卸载范围、缓存状态和旧版本回滚结果 | 安装状态可识别、可撤销、可恢复 | 调用时机正确，或更新值得自动化 |
| 产品行为 | 两个运行端的新会话场景、预期与实际结果 | 观察到的版本在这些场景中符合方法介入合同 | 真实任务中收益高于打断和模型成本 |
| 投入产出 | 真实任务结果、接受或拒绝、返工、询问、时间和可取得的模型用量 | 为保留、收紧、扩展或退役方法提供依据 | 未来任务一定得到相同收益 |

证据必须标明运行端、版本、环境、测试输入、预期、实际结果和可复查位置。无法低成本取得的时间或模型用量可以记为未知，不为补齐数据另建遥测系统。

## Skill 评估证据

Skill 评估把“是否触发”和“触发后是否完成目标”分开记录。`evals/evals.json` 只保存提示、输入、预期触发结果和可观察断言；`baseline`、`with_skill`、`old_skill` 结果由目标运行端外部产生，仓内 `tools/skill_eval/skill-eval.ts` 只做格式校验与确定性汇总。

| 评估读数 | 可以说明什么 | 不能说明什么 |
| --- | --- | --- |
| 触发准确率、误触发、漏触发 | description 在这批提示上的召回边界 | 未来所有用户提示都相同 |
| 行为用例通过率、断言通过率 | 配对运行中可观察结果是否改善 | 模型内部推理正确，或真实任务收益必然提高 |
| Token／耗时差异 | 本批运行的成本变化 | 跨客户端、跨模型或未来版本的固定成本 |
| 静态合同与汇总工具通过 | 评估包和结果统计可机械复核 | Skill 已安装、已加载或已在运行端生效 |

缺失配对结果、非法结果和 `unknown` 必须显式保留；它们不能折叠为通过，也不能用静态检查替代真实客户端证据。

## 后续 Plugin 实验的最小行为场景

后续 `grilling` Plugin 实验至少要在 Codex 与 Claude 的新会话中分别检查以下场景。这里定义的是预期，不是已经发生的结果。

### 1. 用户直接请求

用户直接点名 `grilling` 后，Agent 可以进入方法，不再重复询问是否使用它。

### 2. Agent 建议，用户接受

Agent 先用一条短消息说明新情况、影响、建议、额外成本和普通出口。用户明确接受后，Agent 才开始方法问询；不能要求用户因为已经说“同意”而再输入一次命令。

### 3. 普通任务或只有复杂度

任务目标清楚、风险低，或只是“看起来复杂”时，Agent 可以推荐普通路径或做一次轻量选择，但不能直接展开 `grilling` 问卷。

### 4. 用户拒绝建议

用户选择普通路径后，Agent 继续完成原任务。同一方法和同一理由不能换一种说法后再次出现；只有会改变判断的新证据才能重新建议，并要说明新旧差异。

### 5. 手动入口

用户能通过对应运行端提供的显式语法调用 `grilling`。实验要记录实际显示的命令名：目标是 `/grilling` 与 `$grilling`；如果 Plugin 命名空间是运行端的强制规则，也要如实记录，不能把期望写成已经实现。手动入口可用不代表自动调用已经关闭。

### 6. 降级、换方法或退出

进入方法后，用户或 Agent 可以因为收益不足、成本过高、问题已经清楚或方法不合适而改变路径。交接要保留原任务、已确认决定和仍未知内容，退出后停止剩余问询。

### 7. 实施前确认

Agent 自己调查能够查明的事实，只让用户决定价值、偏好和边界。依赖这些决定的实现必须等人话总结得到确认；无关的只读调查可以继续。

完整的用户可见规则仍以[方法介入合同](https://github.com/Eridanus117/agent-system-foundry/blob/main/product/method-intervention.md)及其[验收场景](https://github.com/Eridanus117/agent-system-foundry/blob/main/product/method-intervention-scenarios.md)为准。

## 自动调用的首次试验

首次 Plugin 实验允许 Agent 在两个运行端自动加载 `grilling`，同时保留手动入口。这是已批准的试验输入，不是方法已经合格的证据。

判定依据是上述行为场景，而不是配置文件中某个布尔值：

- 能自动加载，但未经同意就开始问询：失败；
- 能自动加载，在建议后等待选择：继续验证；
- 用户接受后仍被迫再输入命令：自动调用方案未通过；可作为该运行端的显式回退，并记录额外成本；
- 频繁误触发或不能稳定等待同意：只把失败的运行端收紧为命令入口；
- 自动调用没有可观察收益：缩小触发范围、保持命令入口或退役。

## 结构、安装与配置的失败回退

| 失败 | 回退方向 | 不允许的做法 |
| --- | --- | --- |
| 一个 Plugin 目录不能同时服务两个运行端 | 保留共同来源，生成两个自包含安装包 | 手工维护两份共同方法正文 |
| 运行端不能安全接受另一端的扩展字段 | 把特有包装放入各自安装产物 | 假装未知字段一定会被忽略 |
| 一个发现目录文件不能满足两端 | 保留 Codex 与 Claude 各自的发现投影 | 用路径相似推断字段语义相同 |
| 自动调用不能守住用户同意边界 | 只把失败的运行端收紧为命令入口 | 因一端失败而无证据地限制另一端 |
| 安装试验不能与现有用户配置隔离 | 停止并请求一次明确、可恢复的配置变更授权 | 直接覆盖或手工清理无关配置 |
| 卸载或回滚会触碰无关资产 | 停止并缩小命令目标 | 删除其他 Marketplace、Plugin、Hook 或缓存 |

回退只改变失败的物理实现，不改变共同正文只保存一次、普通路径完整有效、问询前需要同意等上层合同。

## 结果保存在哪里

本文保存证据要求，不保存运行结果。后续 Plugin 实验的 Issue 或 PR 应记录具体命令、版本、环境、输入、实际结果、证据链接、清理状态和仍未知项。

低成本取得且会改变决定的数据才值得持续记录。是否建设月度上游检查，要等至少一次手工回顾产生真实成本和行动价值后再决定。

## 禁止越权的结论

- 公共格式通过，不等于两个运行端都能安装。
- Claude 校验通过，不等于 Codex 兼容。
- 安装成功，不等于自动调用和同意边界正确。
- 行为场景通过，不等于 `grilling` 的收益高于普通路径。
- 首个样本有效，不等于已经得到完整“升级思考”。
- 内容进入 GitHub，不等于自动成为可信知识。
