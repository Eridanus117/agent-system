# 候选与两面的形状

一个候选一块，四样齐；最后是推荐与请主人定的那一句。

```
决定｜在选什么；这轮不定什么；谁受影响
基线｜已确认的需求；现状；尝试分支与旧字段（只当证据）
未知｜还没查明的；谁去量
候选 A｜一句话；碰到的接口／模型／存储／迁移
  支持｜…
  反对｜…
  最大风险｜…
  可逆性｜双向门（改回去只要…）／单向门（一旦…就回不去）
候选 B｜…（同上四样）
推荐｜暂定 A；放弃 B 因为…；推翻条件：一旦…就换 B
请你定｜确认 A，或说哪条不对
```

## 例子：命令行笔记工具的本地索引放哪

```
决定｜`notes search` 的全文索引存在哪；这轮不定分词器
基线｜现在每次搜索全量扫 Markdown（3000 个文件约 1.2 秒）；尝试分支把索引写成一个 JSON 大文件
未知｜笔记目录会不会长到 3 万个文件；谁去量：问主人的增长速度
候选 A｜SQLite FTS5 单文件；碰：新增依赖 better-sqlite3、索引更新钩子
  支持｜增量更新、查询毫秒级、单文件好备份
  反对｜原生依赖跨平台要编译；索引与笔记可能不一致
  最大风险｜Windows 上安装失败
  可逆性｜双向门：删掉索引文件回到全量扫
候选 B｜JSON 索引文件（尝试分支）；碰：一个写入点
  支持｜零依赖、已跑通
  反对｜每次更新整文件重写；3 万个文件时读写都是秒级
  最大风险｜索引文件损坏后静默返回旧结果
  可逆性｜双向门
推荐｜暂定 A；放弃 B 因为增长到 3 万时不可用；推翻条件：主人说目录十年内不过 5000 个文件，则 B 够用
请你定｜确认 A，或告诉我目录的增长速度
```
