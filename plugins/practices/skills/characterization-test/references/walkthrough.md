# 走读清单

清单是测试注释逐行抄出来的那一面；每一步的写法是「看〈入参字段〉= 〈值〉→〈进或跳过哪个分支〉→〈数怎么变〉（〈注释与实现的出入〉）」。

## 形状

```
入参｜<那条真实请求的关键字段>
走读｜
  1 看 <字段> = <值> → <进/跳过哪个分支> → <数值变化>（<注释与实现的出入>）
  2 …
  结果｜<老代码对这条入参的实际输出>
假设｜<拿不出证据的那几行>
未触发｜<这条入参没走到的分支>
请否走读；哪一步不对写在那步下面，我重走。
```

## 例子：运费计算

```
入参｜模板 1032（first=18，next=4），目的地新疆，weight=3.2，vip=false，cod=false
走读｜
  1 看 weight = 3.2 → 进续重分支 → 18 + 3 × 4 = 30（注释写「按 0.5kg 进位」，实现是 Math.ceil 向上取整到 1kg）
  2 看 vip = false → 跳过 vip 分支 → 30 不变（注释写「vip 免续重」，实现是 unit / 2 打五折，本条未触发）
  3 看 region(新疆) = 西北，surcharge = 3 → 进区域加价 → 30 + 3 = 33
  4 看 cod = false → 跳过 → 33
  结果｜33
假设｜区域表里有没有「新疆」单独一行，代码里看不出；calc 是不是唯一入口
未触发｜vip 折半、cod 加 2
请否走读；哪一步不对写在那步下面，我重走。
```

对应的测试，每个断言一行注释：

```java
// 看 weight = 3.2 → 进续重分支 → 18 + 3 × 4 = 30（注释说 0.5kg 进位，实现是向上取整到 1kg）
// 看 vip = false → 跳过 vip 分支 → 30 不变（注释说免续重，实现是打五折，本条未触发）
// 看 region(新疆) = 西北，surcharge = 3 → 进区域加价 → 33
// 看 cod = false → 跳过 → 33
assertEquals(33, calc.calc(req(1032, "新疆", 3.2, false, false)));
```
