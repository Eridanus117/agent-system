# 坏味道基线

来源：Matt Pocock 的 code-review（revision 6acc160），MIT；坏味道本身出自 Fowler《重构》第 2 版第 3 章，中文名按中译本。仓里什么标准都没写时这份基线也生效，两条规矩绑着它：

- **仓里的标准优先。** 仓里文档化的标准永远赢；它明写允许的写法，基线里对应的坏味道就不报。
- **一律是判断题。** 每条坏味道都是带标签的启发式（「疑似依恋情结」），从来不是违例；和任何标准一样，工具已经强制的不报。

给 Standards 子代理时把下表**全文贴进去**，子代理没有别的途径拿到它。每条读作「是什么 → 怎么改」，拿它对着 diff 找：

- **神秘命名（Mysterious Name）**：函数、变量或类型的名字看不出它做什么、装什么。→ 改名；想不出诚实的名字，设计本身就是糊的。
- **重复代码（Duplicated Code）**：同一段逻辑形状在改动里的多个 hunk 或文件出现。→ 抽出共同形状，两处都调它。
- **依恋情结（Feature Envy）**：一个方法碰别的对象的数据比碰自己的多。→ 把方法搬到它依恋的数据那边。
- **数据泥团（Data Clumps）**：同几个字段或参数总是结伴出现（一个想出生的类型）。→ 捆成一个类型传。
- **基本类型偏执（Primitive Obsession）**：用基本类型或字符串顶替一个该有自己类型的领域概念。→ 给这个概念一个小类型。
- **重复的 switch（Repeated Switches）**：对同一类型的同一个 `switch` 或 `if` 级联在改动里反复出现。→ 换成多态，或两处共用一张 map。
- **霰弹式修改（Shotgun Surgery）**：一个逻辑改动逼着 diff 里散改很多文件。→ 把一起变的东西收进一个模块。
- **发散式变化（Divergent Change）**：一个文件或模块因为几个不相干的原因被改。→ 拆开，让每个模块只因一个原因变。
- **夸夸其谈通用性（Speculative Generality）**：为 spec 没提的需要加的抽象、参数或钩子。→ 删掉；内联回去，等真需要再说。
- **过长的消息链（Message Chains）**：调用方不该依赖的长串 `a.b().c().d()` 导航。→ 把这段路藏进第一个对象的一个方法。
- **中间人（Middle Man）**：一个类或函数基本只是往下转发。→ 砍掉，直接调真正的目标。
- **被拒绝的遗赠（Refused Bequest）**：子类或实现者对继承来的大部分东西视而不见或全盘覆盖。→ 去掉继承，改用组合。
