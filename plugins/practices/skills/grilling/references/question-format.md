# 一轮一题的形状

一轮只递一题，题里带自己的推荐答案和一个具体例子，然后停下等主人。下面是一对输入输出。

## 输入（主人的方案）

> 给内部 CLI `notes` 加 `sync` 子命令，把本地 Markdown 笔记同步到自建 WebDAV。约 3000 个文件，一个人用，台式机和笔记本都会改。想法：每次全量上传，冲突以本地为准。

## 输出（第一轮）

```
❓ Q1 · 同步是单向还是双向？
你在两台电脑上都改笔记。「每次全量上传、冲突以本地为准」是单向推送：
台式机上周改了 A.md，今天在笔记本上跑 sync，笔记本上的旧 A.md 会把服务器上的新版本盖掉。
这一题定了，后面「怎么判冲突」「要不要增量」才有得问。

➡️ 我推荐：双向，以修改时间新的一方为准，冲突时两份都留（另存 A.conflict.md），
   因为你的场景是两台机器交替编辑，单向推送迟早丢东西。

你定：单向推送 ／ 双向按时间 ／ 双向留冲突副本 ／ 其他。
```

要点：只有一题；题干里有一个具体的丢数据例子；有推荐和理由；选项面完整；问完停下。
