# 正文怎么写

来源：Anthropic 的 skill 写作指南、Matt Pocock 的 writing-for-agents、superpowers 的 writing-skills 里对本工作区仍成立的部分（取舍见 [vendor-adoption.md](./vendor-adoption.md)）。

## 骨架：五节

1. **什么时候用**：触发与不触发各一段。不触发那段写清该归谁。
2. **步骤**：有序，每步有完成判据（能分辨「做完没做完」）。先磨清晰度，再看要求量。
3. **产出**：列出会留下什么。
4. **出口**：一个出口就写一个，说清到此为止、后面归谁。
5. **为什么在哪**：指向 issue、ADR、词汇表，不在正文里重新论证。

## 写法

- 祈使句写步骤；解释为什么（一句就够），不堆全大写的 MUST／NEVER。
- 输出有固定形状的，给一个骨架加一对输入输出例子；例子用用户原话里的对象，不用 X／Y 占位符。
- 正面陈述目标行为。禁令会把被禁的行为拖进上下文；只在纪律型失败（有诱惑走捷径）时用禁令，并同时给出正面目标。
- 按失败类型选表达形式：纪律型失败用规则加「借口对事实」表；输出形状错用配方与模板；漏要素用必填槽；条件行为用可观测的条件句。
- 能用脚本或测试机械保证的，不写成文字。
- 不复述环境：目录结构、命令帮助、配置项都是会过期的缓存，写「去查」而不是抄。
- 术语按词汇表；概念优先用业界名词，首次附英文；自造词当场定义并标「自造」。
- 想清楚类的 skill（clarify、grill 这类）加三条：一轮只递一题；说平语，不用黑话；先给具体例子再问。

## 剪枝四查（写完过一遍）

1. 单一真相源：同一句话只在一处。
2. 环境本身是真相源：能一条命令查到的不抄进来。
3. 逐行查相关：这一行不在，agent 会做错什么？答不上来就删。
4. 逐句猎无效句：模型默认就会做的，删整句而不是改词。

## 描述

一句话，「做什么、什么时候用」，给人看，中文加英文尾。不写触发词堆叠，不写「一律」「必须先」这类路由句；路由归路线真源。

## 长度

正文不超过 500 行是硬线；软线是「每一行都在，且没有一行重复」。不为凑短砍掉真正的步骤。
