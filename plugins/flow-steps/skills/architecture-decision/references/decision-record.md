# 方案一节的形状

写进这件事的记录（spec issue 评论、ADR 草稿或 PR 正文「为什么」），七行；候选与两面的展开按 `tradeoff-analysis` 的 candidates.md。

```
决定｜这轮要决定什么；本次不决定什么；谁受影响
基线｜已确认的需求（来源）；master 现状（来源）；尝试分支（来源）；外部约束
未知｜还没查明的；为什么未知；补证代价
候选｜A、B（必要时 C）；各自边界、代价、失败后果
两面｜每个候选的支持、反对、最大风险、可逆性
推荐｜暂定选择；放弃的替代；推翻条件
请你定｜确认推荐与剩余未知；确认前不实现
```

## 给主人的那一句

对话里只摆待定的那一件事，事实与展开留在记录里，主人一个字能答：

```
请你定｜D-1 承载方式：暂定 A（规范表加适配层）；B（JSON 列）在目录不长时也够。回「A」「B」，或「查证：<问题>」
```

主人回「查证」就开 `impact-analysis`；回「不对」就回第 3 步重出候选；没点名的决定保持待确认，不因顺带提及而当作确认。
