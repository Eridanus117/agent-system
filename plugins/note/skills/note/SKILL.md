# 沉淀与找回知识

Markdown + git 是正文真源；Rhizome 负责作者契约与校验，Memex 负责检索投影，`index.md` 负责人工导航与故障降级。当前实例：

- **个人知识库**：当前工作区根目录下的 `desk/knowledge/`（2026-09-06 由独立仓合入 desk）
- **工作知识库**：当前工作区根目录下的 `logistics-kb/`

路径从当前工作区已有入口和本机有效源仓登记解析；不要求用户记路径，不写死盘符、用户名。旧知识库内容一律只读参考，不作为新笔记落点。

## 执行

1. **归属与规则**：按问题选择目标库，直接读目标库 `AGENTS.md`；归属、文件名、正文、合并与索引规则以它为准。只沉淀耐用结论、关键证据和有复用价值的疑问，不收任务状态或过程流水账。
2. **先找回**：按[知识闭环命令](./references/knowledge-loop.md)确认当前可调用的入口，用现实问法检索，再读 `index.md` 和候选正文核实。工具失败或结果不足时做同义词文件检索；空结果不等于没记过。仅查询时直接用正文回答并标来源，不新建笔记，也不让用户重述已有结论。
3. **合并或新建**：按目标库规则优先更新已有正文；确认本次写入所有权后才改文件，同时更新人工索引。不强制用 `rhizome new`：目标库要求中文文件名等不适用时，直接按其契约写 Markdown，再校验。
4. **校验与可找回**：跑目标库现有校验；按命令 reference 只编译目标源，随后从同一正常入口用现实问题查询，核对 identity／路径并回读正文。只看到命中元数据，不算找回完成；不默认启动向量服务或计费模型。

索引失败不回滚已保存正文。明确报告失败命令、退出码／错误、正文保留位置与文件检索结果；未完成编译或回读时不能说「已同步／下次可找回」。

## 收尾

只暂存本次拥有的文件并按目标仓规则提交，不能绕过 hook。报告新建／更新或仅找回、库和正文位置、校验与检索结果，以及未沉淀的开放疑问。部署或索引仍受阻时分开说明，不把源码修改、临时实验或局部成功当作日常入口已经生效。
