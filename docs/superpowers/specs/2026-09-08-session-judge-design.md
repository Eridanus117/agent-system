# 会话评分与回放台（session-judge）：设计

日期：2026-09-08，第二版。第一版把它设计成「给主人读的判决表」，主人指出方向错了：主人不该是读者。经 clarify 收口后的三行结论见文末。原型在分支 `proto/session-judge`。

## 一句话

让 agent 像学生做练习题一样自己变好：一套固定的题、一份它改不了的评分、改错重做。主人只做两件事：一开始亲手判十道题当标准答案，以后偶尔抽查有没有作弊。

## 三个部件

### 部件一：题库（回放）

一道题 = 一个真实会话的开场：主人的第一句话、当时在哪个仓、哪个 commit、用哪个 CLI。题从真实会话里截，不编。第一批三道：

- 「利用我的 token 优化自己」那个会话（它自己建了 `mounts` 包）。
- 本会话改 agent-config 那一段。
- 任一 OMP 会话。

做题 = 在一个干净的 worktree 里检出那个 commit，用**候选版本**的规程和规则，无头起一个会话喂那句开场，跑到第一道门为止（agent 第一次停下来等主人）。第一版只跑到第一道门：最要紧的几件事都发生在门之前——有没有先 brainstorming、有没有写计划、动手之前有没有停。跑到门之后需要替主人答话，第二版再做。

题库放私有仓 agent-config（`80-agent配置/60-回放题库/`），因为开场是主人原话。工具代码放公开仓 agent-system。

### 部件二：评分

四层，从便宜到贵：

1. **抽取器**（确定性程序）：把一份会话记录压成一屏时间线：主人每句话、agent 每次发言的前 80 字、每次工具调用（调了哪个 skill、写了哪个文件、跑了什么命令，push 与测试命令打标记）。认 Claude Code 与 OMP 两种格式。
2. **机械检查**（确定性程序）：只看顺序和有无。第一次写代码之前有没有 brainstorming、有没有计划文件、有没有主人发言；有没有跑测试；每次 push 之前主人最近一句是什么。这些不用 AI。
3. **评委**（干净会话里的 AI，和干活的不是同一个模型，默认 Haiku，可换 OMP 的 GPT）：拿固定判据看时间线，判机械检查判不了的事：计划有没有内容、问的问题是不是在澄清、门前那句是不是真的在等主人。四值：符合、不符合、不适用、判不了，每条引用事件编号。
4. **标准答案**（主人）：十道题，主人亲手判每一格。评委的判决和标准答案对不上超过两成，评委不算数。

判据是一份 markdown，随 git 有版本，改它走 PR。判据里写明常设授权（第一版一条：推 desk 的记录类不用批）。

### 部件三：改错重做

agent 改一条规程或规则 → 在候选分支上把题库跑一遍（每道题跑三次，看多数）→ 分数进 PR 正文 → 分高留、分低退。第一版这一步由 agent 手动跑、手动贴；夜里自动循环是以后的事。

## 主人要做的两件事

1. **判十道题**。工具把时间线和评委的判决摆出来，主人逐格说对或不对，几分钟一道。判完之前，评分不算数。
2. **抽查**。每月抽几份评委判过的，看它有没有被糊弄。

## 四条规则，一条防一种砸法

主人 2026-09-08 定：「都会发生，没法预判，用规则防。」

| 会怎么砸 | 规则 | 工具怎么落实 |
|---|---|---|
| 建好了没人用 | 改规程或规则的 PR 必须附评分结果，否则不合入 | PR 模板一行「评分结果」；CI 检查正文有没有 `sj` 的输出块 |
| 标准答案一直没判，评分变瞎评 | 十道题判完之前，`sj score` 拒绝出分 | 工具启动先数标准答案，不够十道直接报错退出 |
| 学生学会应付评分 | 留几道「得满分就是作弊」的题；顺序类的事只信机械检查不信评委 | 题库里放两道空壳会话（调了 brainstorming 但没问问题、计划文件是空的）；评委给它满分即报警 |
| 同时改规程和评分标准，分数变了不知道谁引起的 | 一次 PR 只许改其中一样 | 评分输出带两个 SHA（规程的、判据的）；改规程的 PR 引用的评分必须用 main 上的判据；改判据的 PR 只看和标准答案的一致率 |

## 落哪

| 东西 | 放哪 | 为什么 |
|---|---|---|
| 工具代码 `packages/session-judge`，`bin` 名 `sj` | agent-system（公开） | 方法的工具仓，与 `sk` 并排；不含主人内容 |
| 判据 `rubric/default.md` | agent-system，包内 | 随 git 有版本，改它走 PR |
| 题库、标准答案、哨兵题 | agent-config `80-agent配置/60-回放题库/`（私有） | 含主人原话；agent-config 已是方法改进证据的家 |
| 每次评分与回放的产物 | 本机 `~/.agent-system-state/session-judge/` | 含原话，不入仓 |

## 命令

- `sj extract <会话文件>`：出时间线。
- `sj judge <会话文件>`：机械检查加评委，出判决表。
- `sj anchor <会话文件>`：主人判标准答案，逐格确认或改。
- `sj replay <题> --candidate <分支>`：在候选分支上做一道题，到第一道门。
- `sj score --candidate <分支>`：整个题库做三遍，出分数和两个 SHA。标准答案不够十道则拒绝。
- `sj list`：列最近会话。

## 分两片建

- **第一片：评分。** 抽取器、机械检查、评委、判据、`sj anchor`、标准答案闸门、哨兵题。验收：本会话与「优化自己」那个会话都能判；本会话「门前停过」一条因时间线含 agent 发言而判对；推 desk 不再被列为无批准；两道哨兵题评委不给满分；主人判完十道后一致率算得出来。
- **第二片：回放与规则接线。** `sj replay`、`sj score`、两个 SHA、PR 模板与 CI 检查。验收：拿一条真实的规程改动，在候选分支上跑出分数并进 PR。

每片一个实施计划、一个 PR。第一片先做。

## 不做

跑过第一道门之后替主人答话；夜里自动循环；自动改判据；读工具结果正文；给建议。

## 错误处理与测试

- 文件不存在或格式不认识：报错退出，不猜。记录缺信息：抽取器照出时间线，评委给「判不了」。评委会话失败或输出不合格式：重试一次，再失败写「评委失败」附原文。
- 测试：抽取器与机械检查用脱敏 fixture 逐行断言；评委运行器只测拼装与解析，用假评委命令；不做端到端自动测试，验收靠真实会话人工核。

## 术语对照（业界名字，正文不用）

题库回放 = replay / golden set；评委 = LLM-as-judge；标准答案 = anchor / golden labels；哨兵题 = canary；学生应付评分 = Goodhart；整个形态 = autoresearch 模式（Karpathy，2026-03）。

## clarify 三行（2026-09-08 主人认可）

1. 真正的问题：不是「建一个会话裁判」，而是「agent 改自己的规程时，要有一把它改不了的尺子和一套不变的题；主人只在开头亲手判十道题，以后偶尔抽查」。
2. 值不值得解：值得。顶层目标是「主人只在门上拍板」，现在每改一条规程都靠感觉；「优化自己」那个会话没有尺子就自己建了个包，是已付的代价。
3. 往哪个方向解：照 autoresearch 的形态自建小的；四条规则防四种砸法；排除给主人读的报表与直接装现成优化器。
