# 证据与记录里的本机用户名换成 `<user>` 占位，不改写 git 历史

## 背景与问题（Context and Problem Statement）

ADR-0002 定下「既有违规逐条显式豁免」，理由之一是 `_archive/`、`work/`、`openspec/changes/archive/` 里的历史证据改写就等于篡改证据。PR #99 按 ADR-0002 第 4 步清掉 6 个活文件并收缩了豁免之后，main 上还剩 29 个文件含本机家目录路径里的用户名（两台机器的两个用户名）：

- 历史证据目录里 25 个（`work/` 14、`_archive/` 7、`openspec/changes/archive/` 4），都在内容豁免之内。
- `plugins/clarify/skills/clarify/evals/runs/2026-09-02/` 下 4 个 jsonl 评测记录不在豁免里。之所以没被门禁拦下，是因为路径是 JSON 转义的双反斜杠写法，`windows-home` 规则漏掉了（#100）。

规则补漏以后这 4 个文件会被拦下，所以必须先定一件事：证据与记录里的本机用户名，是继续豁免，还是清掉？

## 决策驱动因素（Decision Drivers）

- 公开仓的当前 tree 不该带本机用户名，门禁的 `local-path` 规则就是为这个立的。
- 证据的意思不能变：路径结构、行号、字节以外的内容都要保持不变。
- 用户名已经在公开的 git 历史里；强推改写历史会让已有 PR 与 fork 的引用失效。

## 考虑过的方案（Considered Options）

| 方案 | 做法 | 适用场景 | 代价 |
|---|---|---|---|
| A 维持 ADR-0002 | 证据不动；补漏后把 4 个 jsonl 加进内容豁免 | 用户名不算敏感，且已在历史里公开 | 用户名继续留在公开 tree 里；豁免清单变长 |
| B 当前 tree 换占位，不改历史 | 路径前缀里的用户名一律换成 `<user>`，其余字节不动；git 历史保留 | 不想在当前 tree 里继续公开，也不愿强推 | 历史里仍查得到；证据文件出现一次机械替换的 diff |
| C B 加上改写历史 | 在 B 的基础上用 filter-repo 一类工具改写全部历史并强推 | 必须真正抹掉 | 公开仓强推：已有 PR、fork、外部链接指向的提交失效；GitHub 缓存与 fork 里的旧对象未必清得掉 |

## 决定结果（Decision Outcome）

选 B（负责人 2026-09-14 定）。只把本机家目录路径里的用户名机械地换成 `<user>`，这不改变证据说了什么，所以不算 ADR-0002 担心的「篡改证据」；ADR-0002 里「证据不改写」一条就此收窄为：除用户名占位替换之外，证据不改写。不选 A：公开 tree 继续带用户名，与 `local-path` 规则的初衷相违。不选 C：强推公开仓的代价大于从历史里抹掉一个已经公开的用户名的收益。

接入顺序（同一个 PR，可整体 revert）：

1. `local-path` 规则补漏：`windows-home` 分隔符允许连写，`posix-home` 覆盖 `/mnt/<盘符>/Users/`；补负面用例，以及 `<user>` 占位放行的正面用例。
2. 当前 tree 里 29 个文件的用户名换成 `<user>`，逐行核对改动只有这一处替换。
3. 三个历史目录的内容豁免暂不收缩：实测去掉这三条豁免后，门禁仍会拦下 4 处内网地址（`private-ipv4`）；要不要清掉这些地址再收缩豁免，另议。

### 后果（Consequences）

- 好的：当前 tree 里不再有本机用户名；以后新增的 JSON 转义写法与 WSL 写法也会被门禁拦下。
- 坏的或要承担的：git 历史里的旧提交仍含用户名；证据文件多出一次机械替换的提交。
- 回退：revert 本 PR 即可，没有仓库设置或外部状态要单独恢复。

### 确认（Confirmation）

- `git grep -i` 在 main 上查不到这两个用户名；按 `Users`／`home` 路径段列出全仓用户名，只剩测试里的合成名（`someone`、`alice`）。
- 用补漏后的规则扫 main 的 HEAD：`status: allowed`；扫本 PR 之前的 main：`blocked`，拦下的正好是那 4 个 jsonl。
