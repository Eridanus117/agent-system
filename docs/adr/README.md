# 架构决策记录（ADR）

本目录存放架构决策记录（Architecture Decision Record，ADR），模板用 MADR（Markdown Any Decision Records）。2026-09-04 负责人裁定采用。

## 什么时候写

改动按分量分三档，只有第二档写 ADR：

| 分量 | 方案放哪 | 改动放哪 |
|---|---|---|
| 小，看 diff 就能判 | PR 正文，按 `.github/PULL_REQUEST_TEMPLATE.md` 四节 | 同一个 PR |
| 有备选要比较、决定会比代码活得久 | 本目录一个 ADR 文件 | 同一个 PR 带上 ADR，或 ADR 先合再实现 |
| 大、跨仓、改产品边界 | 负责人的提案与裁决流程（仓外） | 裁定后另开 PR |

判据一句话：日后有人会问「当初为什么这么选」的，写 ADR。

## 怎么写

- 文件名 `NNNN-短标题.md`，四位编号递增，标题用中文。
- 复制 `template.md`，节名不改；小决定每节一两句，不为格式凑字。
- `status` 取值：proposed（提案，PR 草稿阶段）→ accepted（负责人裁定采用）；被后来的决定取代时改为 `superseded by ADR-NNNN`，不删旧文件。
- 「考虑过的方案」一节至少两条，每条写适用场景与代价；只有一条路的决定不需要 ADR。
- 「确认」一节写成能观测的现象，落地后回来补实际结果。
