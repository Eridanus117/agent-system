## 已核实的 Orca CLI 证据

以下字符串和边界按设计原文记录，不扩展为未验证的宿主行为：

- Orca runtime 状态为 ready，当前运行版本为 `1.4.192`。
- `orca worktree create --agent <id>` 支持在工作树首个终端启动指定 Agent。
- 当前 CLI 指南明确示例和已知 Agent ID 包括 `claude`、`codex`、`omp`、`pi`、`grok`；同时允许其他已安装的 TUI Agent（generic installed TUI providers）。
- `orca automations create --provider <agent>` 是调度入口。
- 调度支持 `hourly`、`daily`、`weekdays`、`weekly`、5-field cron 和 RRULE；目标包括 repo、已有 workspace、project、project host 和远端 runtime；选项包括 `precheck`、`fresh-session`、`reuse-session`、timezone、missed-run grace 等。
- `orca agent-context --json` 提供机器可读的 CLI 合同，但当前没有单独的“列出全部已安装 Agent provider”命令。
- `Hermes` 未出现在当前 CLI 指南的已知 ID 中，因此在本 change 中保持 `unknown`，不宣称为已核实 Orca provider。
- 接受某个 Agent ID 只证明调度接口允许该标识，不等于该 Agent 已通过 Agent System 的真实启动和观察验收。

## 范围约束与缺口

- 本 change 只正式化 Agent Registry、AgentAdapter、AgentScheduleIntent、Orca automation receipt、DispatchOperation、LaunchObservation 和恢复边界；不在本 Task 实现 TypeScript。
- OMP 与 Claude 的现有 native 装配行为作为迁移基线；Codex、Pi、Grok、Hermes 和其他 provider 需要各自的 native assembly、宿主 probe 和 smoke 证据，不由本索引预先授权。
- 不更新 `openspec/specs/`，不创建真实 Orca automation，不修改 `.orca/`。
- 不将动态任务原文、prompt、凭据或 transcript 写入 ConfigurationRevision、schedule、receipt 或日志；仅保存受控引用、标识和指纹。
- 本索引的归纳说明不是外部来源原文；可实施合同、失败语义和验收场景分别进入本 change 的后续 artifacts。
