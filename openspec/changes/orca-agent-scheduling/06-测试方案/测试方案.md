# 测试方案

## 验证层级

| 层级 | 目标 | 证据/入口 | 通过标准 |
|---|---|---|---|
| OpenSpec 结构 | 验证 change 元数据、中文 artifacts 和任务真源可解析 | `npx openspec doctor`；`npx openspec validate orca-agent-scheduling --strict` | 两条命令均成功；`openspec/specs/` 未改 |
| 领域合同 | 验证 Agent、trigger、target、schedule、dispatch 的不变量 | `packages/control-plane/tests/domain/` 定向 `bun test` | 空标识、空表达式、非法状态转换和未关联事实 fail closed |
| Registry/provider | 验证已知、未知、支持分级和能力 snapshot | `packages/control-plane/tests/contracts/` 定向测试 | 没有 inventory/probe 证据时为 `unknown`，不伪造 `supported` |
| Orca command | 验证 scheduler/dispatch 的结构化 argv、JSON receipt 和失败路径 | 注入 `OrcaCommandPort` 的合同测试 | 不执行 shell 字符串；所有 trigger/target/选项不丢失 |
| SQLite 事实 | 验证 schedule/dispatch 持久化、幂等、迁移和条件更新 | 独立临时 SQLite 集成测试 | 保留历史 OMP/Claude 行；过期 phase/version 更新失败 |
| 应用编排 | 验证创建、取消、派发、precheck 和 reconcile | scheduling application tests | automation 创建不等于 Session success；关联不匹配保留 unknown/incomplete |
| CLI dry-run | 验证 allowlist projection 和无副作用调度预览 | `configs agents`/`configs schedule ... --dry-run` | 不创建 automation、不修改 `.orca/`，输出不含 prompt/凭据/transcript |
| 宿主 smoke | 验证每个 provider 的真实启动、观察和清理 | 版本钉住的 Orca/Agent host smoke | 只有完整分层证据才能将 provider 标为 `supported`；无宿主只能 `unknown`/`degraded` |

## OpenSpec 本 Task 门禁

执行以下精确命令，不运行项目级测试套件：

```text
npx openspec doctor
npx openspec validate orca-agent-scheduling --strict
```

预期两条命令均成功，change 目录结构有效，且不产生对 `openspec/specs/` 或 `.orca/` 的修改。命令输出和退出码写入 Task 1 report；没有运行的项目级测试不填写为通过。

## Orca 合同证据边界

版本匹配的 Orca CLI 证据必须原样记录：runtime `1.4.192`；已知 Agent ID `claude`、`codex`、`omp`、`pi`、`grok`；generic installed TUI providers；以及 `orca automations create --provider <agent>`。`orca agent-context --json` 是机器可读合同证据，但当前没有单独列出全部已安装 Agent provider 的命令。Hermes 未出现在当前 CLI 指南已知 ID 中，测试中保持 `unknown`。

调度合同只验证 Orca 可接受的 provider 标识映射，不据此推导 native launch、实际配置生效或真实任务行为。任何 provider 要进入完整 `supported`，必须分别保存 discovery、probe、assembly、schedule、dispatch、observation、recovery 证据。

## 验收场景

| 场景 ID | 场景 | 前置与输入 | 可观察断言 |
|---|---|---|---|
| AGENT-001 | known Orca provider is discoverable | 使用 CLI 证据中的 `claude`/`codex`/`omp`/`pi`/`grok` descriptor | Registry 返回稳定 Agent ID、provider、sourceEvidence；discoverable 不自动等于 launch supported |
| AGENT-002 | unknown provider is not marked supported | 查询不在证据中的 provider，例如 `hermes` 或任意未知标识 | 返回 `unknown`/`unsupported` 与 evidence reason；绝不返回 `supported` |
| AGENT-003 | stable Role/revision binds to one Agent schedule | 给定一个稳定 Role/configuration revision、一个 Agent ID 和 schedule 请求 | 持久化的 `AgentScheduleIntent` 只绑定该 revision、该 Agent 和一个 scheduleId；修改绑定需新 revision/operation，不覆盖旧事实 |
| AGENT-004 | all supported Orca trigger forms map without loss | 分别输入 `hourly`、`daily`、`weekdays`、`weekly`、5-field cron、RRULE | 生成的结构化 Orca argv/JSON 保留原 trigger 类型和值；不把 cron/RRULE 在 Agent System 内重解释为另一种调度 |
| AGENT-005 | precheck failure produces skipped dispatch | 已创建 schedule，模拟 Orca 到点 precheck 非零退出 | DispatchOperation 进入 `skipped` 并保存受控 reason；不产生成功 dispatch 或伪造 Agent launch |
| AGENT-006 | automation creation does not imply Session success | 注入合法 `--json` automation receipt，但不提供 Agent 启动/观察成功证据 | receipt 只使 operation 进入 `dispatched`；不进入 `succeeded`，Session 结果保持未验证/unknown |
| AGENT-007 | dispatch receipt and observation preserve operation/revision/agent/target hashes | 使用带 operationId、revisionId、agentId、target 和 manifestHash 的 schedule/receipt/observation | 每个持久事实和投影都能回读同一组关联值及 target/manifest hash；缺失或不匹配进入 `unknown`/`incomplete` |
| AGENT-008 | OMP and Claude retain existing activation behavior after terminology migration | 用现有 OMP/Claude adapter 合同和配置 revision 执行定向激活 | OMP 仍传 `--skills`/`--no-skills` 与 launch context；Claude 仍传 `--append-system-prompt`、`--plugin-dir`、`--mcp-config`/`--strict-mcp-config` 并清理 invocation；仅术语/registry wiring 变化 |

## 失败与停止条件

- provider discovery、版本或必需 capability 为 unknown；Role/revision、target 或 trigger 无法验证；或任何关联 hash 缺失：停止并 fail closed。
- Orca 命令非零退出、JSON 无效、receipt 缺少 automationId/provider/source evidence 或取消未获确认：只记录类型化失败，不生成成功事实。
- precheck 失败必须是 `skipped`，不得执行 dispatch。
- 真实 Agent 启动、观察、清理缺失时，不填写 native launch 或 real Agent task PASS。
- 测试若观察到全局配置、`.orca/`、Role source、凭据或 transcript 被写入，立即停止并清理测试临时资产；不得把副作用当作通过证据。

## 证据保存

每次实现阶段运行应使用独立 `runs/<run-id>/`，保存 commit、Orca runtime/provider evidence、输入 revision/target/manifest hashes、命令输出、receipt、observation、清理结果和未验证边界。结构测试与真实宿主 smoke 分开记录；失败输出不得被成功输出覆盖。
