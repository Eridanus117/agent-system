# 测试计划

## 验证范围与层级

| 层级 | 目标 | 工具/入口 | 通过标准 |
|---|---|---|---|
| OpenSpec 合同 | 验证 change 工件、`skip_specs` 和来源合同可解析 | `npx openspec validate repository-baseline-inventory --strict` | 返回 valid，未出现缺失工件或来源合同错误 |
| live spec 回归 | 确认本次资料盘点没有改动三份长期规范 | `npx openspec validate --specs --strict` | 三份 live spec 全部通过 |
| 运行时入口 | 确认自定义 schema、root 和 gitlink 可回读 | `npx openspec doctor`、`npx openspec schemas` | root ok，列出 `delivery-change` project schema |
| 资料边界 | 确认基线只引用路径和状态，不复制私域原文、凭据或任务内容 | 人工检查 01/03/04/05 与 `change-sources.json` | 只有公开路径、事实、推断和可复现命令 |
| 客户端运行阻断 | 记录当前 CLI 真实运行结果，不把源码存在当成功 | `bun packages/control-plane/src/cli/index.ts --help` | 成功或保留实际失败原文；未修复时验收结论不得称 CLI 可用 |
| 回滚 | 确认本 change 可单独移除，不影响 live specs、archive 或源码 | 变更范围检查与版本控制 diff | 只涉及本 change 工件（以及已声明 runtime 初始化状态） |

## 自动化资产

```text
06-测试方案/
├── fixtures/
├── scenarios/
├── runtime/
└── runner/*.ts
```

本轮不新增 runner、fixture 或 runtime 资产：现状基线的关键证据由 OpenSpec CLI 与已执行的 Bun 命令直接产生。未来若增加自动化 runner，必须使用 TypeScript 并将真实运行证据放入独立 `runs/<run-id>/`，不得把运行输出混入本层方案。

## 失败与停止条件

- strict validation 失败时停止，不进入实施任务或验收结论。
- 发现基线文档把历史材料写成当前权威、把源码存在写成实际可用，停止并修正文档。
- 发现任何私域原文、凭据、账号、prompt、transcript、任务 payload 或环境秘密进入本 change，停止并清除后重新检查。
- CLI 运行命令失败可以作为现状证据继续记录，但不得声称控制面端到端可用；若要修复，另开有真实 Requirement delta 的 change。
- 回滚范围无法限定到本 change 时停止，不执行删除或迁移。

## 数据准备与清理

- 所有输入使用仓库内公开文件路径；不复制文件原文到 fixture，不接触用户全局配置。
- 不创建 SQLite、客户端进程、网络发布物或个人状态快照。
- 运行证据只写入本 change 的验收目录；失败证据不得覆盖。
- 本轮没有需要清理的动态资源；若未来新增运行资源，只允许清理本次创建且可明确识别的资源。
